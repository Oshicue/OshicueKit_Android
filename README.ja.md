# Oshicue Kit · Android

[简体中文](README.md) | [繁體中文](README.zh-Hant.md) | [繁體粵語](README.zh-HK.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [ไทย](README.th.md) | [Bahasa Indonesia](README.id.md) | [Bahasa Melayu](README.ms.md)

ライブや旅行の予定を整理し、イベントのタイムテーブルを確認し、物販の支出やイベント日記を記録するネイティブ Android アプリです。**Kotlin、Jetpack Compose、Material 3** で開発され、予定、タイムテーブル、手帳、日記、設定の5つのタブを備えています。

現在のバージョン：**0.5.3（Build 16）**。**Android 8.0（API 26）以降**に対応し、アプリケーション ID は `com.oshicue.kit` です。

## はじめに

1. 署名済み APK をインストールするか、下記の手順でソースからビルドします。
2. 初回起動時には架空のタイムテーブルと手帳のサンプルが読み込まれます。予定と日記は空の状態で始まります。
3. 設定で言語を切り替えるか、各機能の管理画面から自分の JSON ファイルをインポートします。
4. 予定、手帳、日記のバックアップを定期的にエクスポートし、元のタイムテーブルファイルも保管してください。

自分のタイムテーブルを初めてインポートするとサンプルが置き換わり、以後はイベント ID に従って更新または追加されます。手帳も初回の正式なインポートで未編集のサンプルが置き換わりますが、手動で編集したサンプルは保持され、インポート内容と統合されます。サンプルの名称、日付、フライト、場所は試用のための情報です。実際に使う前に自分の情報に置き換えてください。

## 主な機能

### 予定

- Live、フライト、ホテル、レストラン、その他の場所をカレンダーで管理できます。時刻指定と終日の予定、タイムゾーン、住所、メモに対応しています。予定はタイムテーブルの「自分の予定」で選択した公演とは独立しています。
- フライトの出発・到着時刻、タイムゾーン、空港をそれぞれ記録できます。ホテルはチェックインとチェックアウトの時刻を旅程の区切りとして扱います。
- 都市や場所を検索し、外部の地図アプリで位置や経路を確認できます。検索結果からタイムゾーンは自動設定されないため、手動で確認してください。
- 連続する時刻指定の予定について、空き時間や時間の重なりを表示します。終日の予定は移動区間の比較対象になりません。現在、アプリ内での経路所要時間の推定やリアルタイムのフライト照会には対応していません。
- Android のカレンダー編集画面を通じてシステムカレンダーにコピーを保存できます。コピーとアプリ内の記録は別々に編集します。
- 検索、複数条件の絞り込み、複数選択での削除、JSON インポートのプレビュー、予定全体のバックアップに対応しています。

### タイムテーブル

- 日付、イベント、LIVE／物販の種類で絞り込み、会場を横方向、時間を縦方向にスクロールして確認できます。
- 公演をタップすると詳細が開きます。ダブルタップまたは長押しで「自分の予定」に追加・解除でき、詳細画面からも同じ操作ができます。
- 重なる公演は横に並べて表示し、時間の衝突を知らせます。50%、70%、100%、150% の拡大率に対応しています。
- 現在時刻の線は15秒ごとに更新されます。日付をまたぐ公演は表示用タイムゾーンに従って分割されます。複数イベントの表示では、選択したイベントのうち文書内の順序が最初のイベントのタイムゾーンを使います。
- JSON の貼り付けや複数ファイルのインポート、検証、プレビューに対応しています。同じ ID のイベントは全体を更新し、ほかのイベントは保持します。同じバッチ内でイベント ID が重複するとインポートを拒否します。
- イベントの削除には確認が必要です。そのイベントの公演選択は解除されますが、手帳と日記は保持されます。現在、タイムテーブルのエクスポート機能はないため、元のインポートファイルを保管してください。

### 手帳 · Ledger

- カレンダーで日別・月別の物販数量と通貨別の支出を確認し、グループ、メンバー、アバター、物販の種類、イベント情報を管理できます。
- 同じメンバーを複数のグループに所属させ、所属ごとに色と既定価格を設定できます。お気に入りメンバーの設定はすべての所属で共有されます。
- 日付、数量、通貨、単価、イベント情報のスナップショットを記録します。新規記録の単価は、選択日以前の同じメンバー・グループ・種類・通貨の価格を優先し、次に新規追加時に記憶した価格、メンバーの既定価格、0 の順に参照します。単価は手動で変更できます。
- ランキングは日・月・年・全期間に対応し、メンバー合計、グループ別のメンバー、グループ、数量、支出などの観点で表示できます。
- `CNY`、`JPY`、`HKD`、`TWD`、`USD`、`KRW`、`THB`、`IDR`、`MYR` に対応しています。通貨ごとに集計し、為替換算は行いません。`JPY` と `KRW` は整数、それ以外は小数点以下2桁を使います。JSON の `unitPriceMinor` には、通貨の最小単位を整数で保存します。
- メンバーやグループを削除すると、関連情報と所属をアーカイブし、過去の購入スナップショットや統計は保持します。記録管理では絞り込み、一括削除、完全な JSON バックアップとインポートができます。

### 日記 · Diary

- タイトル、本文、要約、タグを書き、「下書き」「整理済み」の状態を設定できます。日付順の閲覧、検索、絞り込みに対応しています。
- 手帳のイベントから日付、名称、都市、会場、住所を取り込めます。日記には独立したスナップショットを保存します。
- 編集が止まって約0.5秒後に自動保存します。編集を完了するか編集画面を閉じると、未保存の内容を保存します。保存に失敗した場合は再試行を案内します。
- Markdown／プレーンテキストのコピー、`.md`／`.txt` のエクスポート、Android のシステム共有に対応しています。「整理済み」は端末内の状態であり、共有しても自動で公開されることはありません。
- 一括管理と完全な JSON バックアップができます。同じ ID で内容も同じ記録は重複を除外し、同じ ID で内容が異なる場合はインポート全体を拒否します。

## JSON テンプレートとバックアップ

| 内容 | 同梱ファイル |

| 予定テンプレート | [agenda-template.json](app/src/main/assets/templates/agenda-template.json) |
| タイムテーブルテンプレート | [timetable-template.json](app/src/main/assets/templates/timetable-template.json) |

| 手帳テンプレート | [ledger-template.json](app/src/main/assets/templates/ledger-template.json) |

JSON ファイルは UTF-8 を使い、対応する機能の画面からインポートし、プレビューの後に確定します。各機能の JSON 構造は異なるため、同じ `schemaVersion: 1` でも相互に流用できません。日記は1件作成してバックアップをエクスポートすると、形式の参考にできます。ソースには日記専用のテンプレートは付属していません。

## ローカルデータと設定

データはアプリの非公開ディレクトリ `filesDir/OshicueKit/` 内の `agenda.json`、`schedule.json`、`ledger.json`、`diary.json`、`settings.json` に保存されます。言語と最後に開いたタブ、タイムテーブルの選択内容も端末内に記憶します。

既定ではシステム言語に従い、未対応の言語では英語を使います。9言語から手動で切り替えることもできます。画面はシステムのライト／ダーク表示に従い、Android 14 以降ではシステムのコントラスト強化設定にも対応します。

主要な記録機能はオフラインで使え、アカウントは不要です。現在、アプリ内のクラウド同期、自動クラウドバックアップ、プッシュ通知によるリマインダー、画像からのインポートは提供していません。場所の検索は端末のジオコーディングサービスに依存します。外部地図、経路、カレンダーの機能は、インストール済みのアプリやサービスによって利用可否が異なり、ネットワーク接続が必要な場合があります。アンインストールやアプリデータの消去前に、手動でバックアップをエクスポートしてください。

## ソースからのビルド

現在のプロジェクト設定と、今回のパッケージ作成に使用した環境は次のとおりです。

| 項目 | バージョン |
| --- | --- |
| アプリのバージョン / `versionCode` | `0.5.3` / `16` |
| 最小 / 対象 / コンパイル Android API | `26` / `37` / `37` |
| Android Gradle Plugin | `9.4.1` |
| Kotlin Compose プラグイン | `2.2.10` |
| Compose BOM | `2026.09.00` |
| Java ソースとバイトコードのターゲット | `17` |
| 今回の検証に使用した Gradle / JBR | `9.8.1` / `25.0.3` |

1. Android Studio でこのディレクトリを開き、Android SDK Platform 37 と必要なビルドツールをインストールします。
2. Gradle の実行に適した JDK を使います。今回の検証では Android Studio 付属の JBR を使用しました。Java のコンパイルターゲット `17` と Gradle を実行する JDK のバージョンは別の設定です。
3. Android Studio に `local.properties` を生成させるか、`sdk.dir` にローカル SDK の絶対パスを設定します。このファイルはコミットしないでください。
4. インストール済みの Gradle を `PATH` に追加し、このディレクトリで次のコマンドを実行します。初回の依存関係の解決にはネットワーク接続が必要です。

ソースには Gradle Wrapper が付属していないため、以下では `gradle` を使います。

```sh
gradle :app:assembleDebug
gradle :app:testDebugUnitTest :app:lintDebug
```

APK の出力先：`app/build/outputs/apk/debug/app-debug.apk`。既定のビルドにはデバッグ署名を使います。現在のプロジェクトには正式リリース用の署名設定がないため、リリース前に設定してください。

今回のパッケージ作成時、対応するソースは **166 件の単体テスト**に合格し、APK の署名とアラインメントの検証にも合格しました。リポジトリには Android の UI 自動テスト一式は含まれていません。地図、システムカレンダー、ファイル選択、共有は対象端末で確認してください。

GitHub にアップロードする際は、`local.properties`、`.gradle/`、`.kotlin/`、`build/`、`app/build/`、ローカル IDE ファイル、署名鍵を除外してください。
