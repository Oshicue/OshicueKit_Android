# Oshicue Kit · Android

[简体中文](README.md) | [繁體中文](README.zh-Hant.md) | [繁體粵語](README.zh-HK.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [ไทย](README.th.md) | [Bahasa Indonesia](README.id.md) | [Bahasa Melayu](README.ms.md)

공연과 여행 일정을 정리하고, 행사 시간표를 확인하고, 굿즈 구매 내역과 행사 일기를 기록하는 네이티브 Android 앱입니다. **Kotlin, Jetpack Compose, Material 3**로 개발했으며 일정, 시간표, 가계부, 일기, 설정의 다섯 탭을 제공합니다.

현재 버전: **0.5.3 (Build 16)**. **Android 8.0 (API 26) 이상**을 지원하며 앱 ID는 `com.oshicue.kit`입니다.

## 빠른 시작

1. 서명된 APK를 설치하거나 아래 안내에 따라 소스에서 빌드합니다.
2. 처음 실행하면 가상의 시간표와 가계부 예시가 불러와집니다. 일정과 일기는 비어 있는 상태로 시작합니다.
3. 설정에서 언어를 바꾸거나 각 기능의 관리 화면에서 자신의 JSON 파일을 가져옵니다.
4. 일정, 가계부, 일기 백업을 정기적으로 내보내고 원본 시간표 파일도 보관하세요.

자신의 시간표를 처음 가져오면 예시를 대체하며, 이후에는 행사 ID에 따라 갱신하거나 추가합니다. 가계부도 처음 정식으로 가져올 때 수정하지 않은 예시를 대체하지만, 직접 수정한 예시는 유지하면서 합칩니다. 예시에 있는 이름, 날짜, 항공편, 장소는 앱을 체험하기 위한 정보입니다. 실제로 사용하기 전에 자신의 정보로 바꾸세요.

## 주요 기능

### 일정

- 캘린더에서 Live, 항공편, 호텔, 식당, 기타 장소를 관리합니다. 시간 지정 및 종일 일정, 시간대, 주소, 메모를 지원합니다. 일정은 시간표의 ‘내 일정’에서 선택한 회차와 별개입니다.
- 항공편의 출발·도착 시간, 시간대, 공항을 각각 기록할 수 있습니다. 호텔은 체크인과 체크아웃 시간을 이동 일정의 기준 시점으로 사용합니다.
- 도시와 장소를 검색하고 외부 지도 앱에서 위치나 경로를 확인합니다. 검색 결과가 시간대를 자동으로 설정하지 않으므로 직접 확인하세요.
- 연속된 시간 지정 일정 사이의 빈 시간이나 겹치는 시간을 표시합니다. 종일 일정은 이동 구간 비교에서 제외됩니다. 현재 앱 내 경로 소요 시간 추정과 실시간 항공편 조회는 지원하지 않습니다.
- Android 캘린더 편집기를 통해 시스템 캘린더에 별도 사본을 저장합니다. 사본과 앱의 기록은 각각 편집합니다.
- 검색, 복합 필터, 다중 선택 삭제, JSON 가져오기 미리보기, 전체 일정 백업을 제공합니다.

### 시간표

- 날짜, 행사, LIVE/굿즈 유형별로 필터링하고 가로로는 행사장, 세로로는 시간을 확인합니다.
- 회차를 한 번 누르면 상세 정보가 열립니다. 두 번 누르거나 길게 눌러 ‘내 일정’에 추가하거나 해제할 수 있으며 상세 화면에서도 같은 작업을 할 수 있습니다.
- 겹치는 회차는 나란히 표시하고 시간 충돌을 알려줍니다. 50%, 70%, 100%, 150% 배율을 지원합니다.
- 현재 시간선은 15초마다 갱신됩니다. 자정을 넘는 회차는 표시 시간대를 기준으로 나눕니다. 여러 행사를 함께 표시할 때는 선택한 행사 중 문서상 순서가 가장 앞선 행사의 시간대를 사용합니다.
- JSON 붙여넣기, 여러 파일 가져오기, 유효성 검사와 미리보기를 지원합니다. 같은 ID의 행사는 전체를 갱신하고 다른 행사는 유지합니다. 한 번에 가져오는 자료 안에서 행사 ID가 중복되면 가져오기를 거부합니다.
- 행사를 삭제하려면 확인이 필요하며, 해당 행사의 회차 선택도 해제됩니다. 가계부와 일기는 유지됩니다. 현재 시간표 내보내기는 제공하지 않으므로 원본 가져오기 파일을 보관하세요.

### 가계부 · Ledger

- 캘린더에서 일별·월별 굿즈 수량과 통화별 지출을 확인하고 그룹, 멤버, 프로필 이미지, 굿즈 유형, 행사 정보를 관리합니다.
- 같은 멤버가 여러 그룹에 소속될 수 있으며 소속별로 색상과 기본 가격을 설정합니다. 즐겨찾는 멤버 설정은 모든 소속에서 공유됩니다.
- 날짜, 수량, 통화, 단가, 행사 정보 스냅샷을 기록합니다. 새 기록은 선택한 날짜 당일이나 이전의 같은 멤버·그룹·유형·통화 가격을 우선 참고한 뒤, 새 기록 추가 시 기억한 가격, 멤버 기본 가격, 0 순으로 사용합니다. 단가는 직접 바꿀 수 있습니다.
- 순위는 일별, 월별, 연도별, 전체 기간을 지원하며 멤버 합계, 그룹별 멤버, 그룹, 수량, 지출 등의 기준으로 볼 수 있습니다.
- `CNY`, `JPY`, `HKD`, `TWD`, `USD`, `KRW`, `THB`, `IDR`, `MYR`을 지원합니다. 통화별로 따로 집계하며 환율 변환은 하지 않습니다. `JPY`와 `KRW`는 정수를, 나머지는 소수점 이하 두 자리를 사용합니다. JSON의 `unitPriceMinor`는 통화의 최소 단위를 정수로 저장합니다.
- 멤버나 그룹을 제거하면 관련 정보와 소속을 보관 처리하고 과거 구매 스냅샷과 통계는 유지합니다. 기록 관리에서 필터, 일괄 삭제, 전체 JSON 백업 및 가져오기를 지원합니다.

### 일기 · Diary

- 제목, 본문, 요약, 태그를 작성하고 ‘초안’ 또는 ‘정리 완료’ 상태를 지정합니다. 날짜별로 살펴보고 검색하거나 필터링할 수 있습니다.
- 가계부 행사에서 날짜, 이름, 도시, 행사장, 주소를 가져올 수 있습니다. 일기는 독립적인 스냅샷을 저장합니다.
- 편집을 멈추면 약 0.5초 뒤 자동 저장합니다. 편집을 완료하거나 편집기를 닫으면 저장 대기 중인 내용을 저장하며, 저장에 실패하면 다시 시도하라는 안내를 표시합니다.
- Markdown/일반 텍스트 복사, `.md`/`.txt` 내보내기, Android 시스템 공유를 지원합니다. ‘정리 완료’는 기기에 저장되는 상태이며 공유한다고 자동으로 게시되지는 않습니다.
- 일괄 관리와 전체 JSON 백업을 제공합니다. ID와 내용이 모두 같으면 중복을 제거하고, 같은 ID의 내용이 서로 다르면 가져오기 전체를 거부합니다.

JSON 파일은 UTF-8을 사용하며 해당 기능의 가져오기 화면에서 미리 확인한 뒤 확정합니다. 각 기능의 JSON 구조가 다르므로 `schemaVersion: 1`이 같아도 서로 바꾸어 사용할 수 없습니다. 일기는 먼저 한 편을 만든 뒤 백업을 내보내 형식을 참고할 수 있습니다. 소스에는 별도의 일기 템플릿이 포함되어 있지 않습니다.

## 로컬 데이터와 설정

데이터는 앱 전용 디렉터리 `filesDir/OshicueKit/` 안의 `agenda.json`, `schedule.json`, `ledger.json`, `diary.json`, `settings.json`에 저장합니다. 언어와 마지막으로 열었던 탭, 시간표 선택 내용도 기기에 기억합니다.

기본적으로 시스템 언어를 따르며 지원하지 않는 언어는 영어로 표시합니다. 아홉 언어 중 하나를 직접 선택할 수도 있습니다. 화면은 시스템의 밝은 모드/어두운 모드를 따르고 Android 14 이상에서는 시스템의 향상된 대비 설정에도 반응합니다.

핵심 기록 기능은 오프라인에서 사용할 수 있으며 계정이 필요하지 않습니다. 현재 앱 내 클라우드 동기화, 자동 클라우드 백업, 푸시 알림, 이미지 인식 가져오기는 제공하지 않습니다. 장소 검색은 기기의 지오코딩 서비스에 의존합니다. 외부 지도, 경로, 캘린더 기능은 설치된 앱과 서비스에 따라 달라지며 해당 서비스에 네트워크 연결이 필요할 수 있습니다. 앱을 삭제하거나 데이터를 지우기 전에 직접 백업을 내보내세요.

## 소스에서 빌드

현재 프로젝트 설정과 이번 패키징에 사용한 환경은 다음과 같습니다.

| 항목 | 버전 |
| --- | --- |
| 앱 버전 / `versionCode` | `0.5.3` / `16` |
| 최소 / 대상 / 컴파일 Android API | `26` / `37` / `37` |
| Android Gradle Plugin | `9.4.1` |
| Kotlin Compose 플러그인 | `2.2.10` |
| Compose BOM | `2026.09.00` |
| Java 소스 및 바이트코드 대상 | `17` |
| 이번 검증에 사용한 Gradle / JBR | `9.8.1` / `25.0.3` |

1. Android Studio에서 이 디렉터리를 열고 Android SDK Platform 37과 필요한 빌드 도구를 설치합니다.
2. Gradle 실행에 적합한 JDK를 사용합니다. 이번 검증에서는 Android Studio에 포함된 JBR을 사용했습니다. Java 컴파일 대상 `17`과 Gradle을 실행하는 JDK 버전은 서로 다른 설정입니다.
3. Android Studio가 `local.properties`를 생성하도록 하거나 `sdk.dir`에 로컬 SDK의 절대 경로를 입력합니다. 이 파일은 커밋하지 마세요.
4. 설치한 Gradle을 `PATH`에 추가하고 이 디렉터리에서 아래 명령을 실행합니다. 처음 의존성을 확인하고 내려받을 때는 네트워크 연결이 필요합니다.

소스에 Gradle Wrapper가 포함되어 있지 않으므로 아래 명령은 `gradle`을 사용합니다.

```sh
gradle :app:assembleDebug
gradle :app:testDebugUnitTest :app:lintDebug
```

APK 출력 위치: `app/build/outputs/apk/debug/app-debug.apk`. 기본 빌드는 디버그 서명을 사용합니다. 현재 프로젝트에는 정식 배포용 서명이 설정되어 있지 않으므로 배포 전에 직접 설정해야 합니다.

이번 패키징 시 해당 소스는 **단위 테스트 166개**를 통과했으며 APK 서명 및 정렬 검사도 통과했습니다. 저장소에는 Android UI 자동화 테스트 모음이 포함되어 있지 않습니다. 지도, 시스템 캘린더, 파일 선택, 공유는 대상 기기에서 확인하세요.

GitHub에 업로드할 때는 `local.properties`, `.gradle/`, `.kotlin/`, `build/`, `app/build/`, 로컬 IDE 파일, 서명 키를 제외하세요.
