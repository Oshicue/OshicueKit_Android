# 時間割 JSON のインポート

[简体中文](IMPORT.zh-CN.md) | [繁體中文](IMPORT.zh-Hant.md) | [繁體粵語](IMPORT.zh-HK.md) | [English](IMPORT.en.md) | [日本語](IMPORT.ja.md) | [한국어](IMPORT.ko.md) | [ไทย](IMPORT.th.md) | [Bahasa Indonesia](IMPORT.id.md) | [Bahasa Melayu](IMPORT.ms.md)

UTF-8 の JSON を使用します。時間割のインポート画面を開き、全文を貼り付けるか、1 つまたは複数の `.json` ファイルやプレーンテキストファイルを選択します。検証に成功するとイベント数と枠数が表示され、確認後に適用されます。プレビューのテキストを編集した場合は、再度検証してください。

## 更新とお気に入り

初回起動時は、東京の起動時刻の正時を基準に、翌日の予定も含む架空の時間割を 2 つ生成して保存し、最初の 2 グループをお気に入りに登録します。見出しにサンプル表示はありません。次回以降は保存済みデータを読み込みます。最初の正式なインポートでは、サンプル状態の時間割を置き換え、サンプルのお気に入りを解除します。その後のインポートでは他のイベントを残し、同じ `id` のイベントの内容全体を置き換えます。更新時は一部の枠だけでなく、イベント全体を用意してください。

グループの `id` はイベント間で共通のお気に入り識別子です。名前を変えても ID を維持すればお気に入りが引き継がれます。LIVE または物販のブロックをダブルタップすると、そのグループのお気に入りが切り替わります。自分の時間割では、選択したイベントと日付に合わせ、お気に入りグループの LIVE と物販をまとめて表示します。時間の重複は有効な予定として受け付け、横に並べて競合を表示します。この表示は時間のみを比較し、移動や両方への参加可否は判断しません。

## フィールド

| 位置 | フィールド | ルール |
| --- | --- | --- |
| 最上位 | `schemaVersion` | 必須の整数。固定値 `1`。 |
| 最上位 | `events` | 必須のイベント配列。インポート画面では 1 件以上のイベントと、全体で 1 件以上の枠が必要。 |
| イベント | `id`, `name`, `city` | 必須の空でない文字列。イベント ID はバッチ全体で一意。 |
| イベント | `timeZone` | `Asia/Tokyo` などの有効な IANA タイムゾーンが必須。 |
| イベント | `venues`, `artists`, `sessions` | 必須の配列。個別のイベントに枠がなくても可。 |
| 会場 | `id`, `name`, `color` | 空でない ID と名前。色は `#RRGGBB` 形式。例：`#78C9EB`。 |
| グループ | `id`, `name` | 必須の空でない文字列。グループ ID はイベント間で維持する。 |
| 枠 | `id`, `artistID`, `venueID` | 空でない枠 ID。同じイベントで定義したグループと会場を参照する。 |
| 枠 | `kind` | `live` または `goods` のみ。 |
| 枠 | `startsAt`, `endsAt` | 秒と `Z` または明示的なオフセットを含む完全な ISO 8601 日時。終了は開始より後。 |
| 枠 | `area`, `notes` | 任意の文字列。省略または `null` 可。 |

会場、グループ、枠の ID は、それぞれイベント内で一意にします。必須文字列に空白だけは使用できません。JSON はコメントと末尾のカンマをサポートしません。未知のフィールドは受け付けますが、アプリには表示されず、再エンコード時にも保持されません。

## 検証と一括インポート

エラーには `$.events[0].sessions[2].endsAt` などのフィールドパスが表示されます。バージョン、型、日付、タイムゾーン、色、重複 ID、参照、長さの誤りは、入力全体の検証を停止します。複数ファイルは結合後にまとめて検証し、ファイル間のイベント ID 重複もエラーになります。いずれかのファイルが失敗すると一部だけのインポートは行いません。インポート画面では、空のイベント配列や、全体に枠がない内容は適用できません。コア形式では、全件削除後の内部状態を保存するために `events: []` を許可しています。

## タイムゾーンと日付をまたぐ枠

`2026-10-14T12:00:00+09:00`、`2026-10-14T03:00:00Z`、小数秒を受け付けます。`12:00`、秒やタイムゾーンのない値は無効です。オフセットは絶対時刻を、イベントの `timeZone` は現地の日付を決定します。各枠の実際のタイムゾーンに合わせて入力してください。夏時間終了時の重複する時刻 `2026-11-01T01:30:00-04:00` と `2026-11-01T01:30:00-05:00` は、異なる 2 つの時刻です。

深夜をまたぐ場合は終了日を翌日にします：`2026-10-14T23:40:00+09:00` → `2026-10-15T00:20:00+09:00`。枠は両日に表示され、各日の範囲に切り取られます。ちょうど `00:00:00` に終了する場合、空の日付は追加しません。人為的な最大時間制限はありません。

異なるタイムゾーンのイベントを同時に選ぶと、現在の画面は、選択されたイベントのうち文書順で最初のイベントのタイムゾーンを日付、時間、詳細に共通使用します。フィルター欄にそのゾーンを表示します。イベント本来の現地時刻を確認するには、そのイベントだけを選んでください。現在時刻の線は実際のシステム時刻を使用するため、固定サンプルの日付が今日とは限りません。

## テンプレートの編集

ページ末尾のリンクから時間割テンプレートをコピーします。`schemaVersion` と `events` を残して安定した ID を入力し、枠をコピーして参照、種類、日時を変更してください。テンプレートのイベント、グループ、予定はすべて架空です。テンプレートは自動インポートされません。
