# 手账使用与数据格式

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

手账按日历记录物贩消费，维护团体、成员、所属关系、代表色及默认价格，并统计数量与消费排名。数据保存在本机，手账备份与时间表、日志备份分开。

## 开始使用

1. 在「成员与类型」新增团体及成员。同一成员兼任多个团体时，使用「关联已有成员（兼任）」添加所属关系，沿用同一个成员编号；同名但编号不同的成员不会自动合并。
2. 为每个所属关系分别设置代表色及默认单价。默认类型有拍立得、WIDE 拍立得、手机合影，也可新增类型；同一类型可设置不同币种价格。成员名称和头像由各团体共用。
3. 点击「＋」，选择日期、成员所在团体、类型、数量、币种与实际单价。切换成员身份、类型或币种会重新带入对应默认价格；没有默认价格时需要填写单价。数量为正整数，单价可以为零。
4. 活动、城市、场馆、地址与备注均可不填。可以建立手账活动，或从时间表选择活动及场馆，复制为手账活动；后续修改时间表不会自动同步到手账。
5. 日历数字表示当天的物贩总数量，不是记录条数。月份卡片显示当月数量及分币种消费；选定日期后可查看成员分团体汇总及逐笔记录。

数量是类型的份数：照片按张，新增券类可按券计。

## 编辑、删除与历史快照

点击日期下的成员卡片：只有一笔消费时直接打开编辑；有多笔时先选择记录。也可展开逐笔记录进入编辑。表单带入原有日期、身份、类型、数量、单价与可选信息，保存只更新该记录。编辑页的「删除这笔物贩」需要确认，删除后数量和金额随之扣除。

在「成员与类型」点击成员编辑资料；团体标题旁的铅笔打开团体编辑。删除成员或团体均需确认：

- 删除成员：归档这个成员及其在所有团体中的所属关系。
- 删除团体：归档团体及该团体的所属关系；兼任其他团体的成员继续可用。

归档资料保留在备份中，已有消费、名称、代表色、单价和统计继续保留。新记录及改选身份只能使用有效所属关系；历史记录仍可保留原已删除身份编辑，选择器会标注「已删除」。资料编辑页没有恢复入口；导入含同编号有效资料的备份可以恢复目录资料，仍须通过完整合并校验。

修改目录名称、代表色或默认价格不会重写已保存消费。编辑消费时，保留同一身份会保留成员、团体及颜色快照；保留同一类型会保留类型名称快照。改选身份或类型时重新取对应快照；实际单价及活动信息按表单保存。保存先校验完整账本，再原子写入本机，失败不会发布部分修改。

## 统计

统计支持日、月、年及生涯范围，可按类型和团体筛选，按成员合计、成员分团体或团体排名。成员人数按筛选后的不同 `memberID` 计算。已归档团体仍可用于历史统计筛选。

数量排名可以合计所有币种的份数，消费排名必须选择一个币种；金额不会混加或自动换汇。汇总按类型列出数量和分币种金额。排名采用竞赛名次，例如 `1、1、3`；同分按编号稳定排序，占比以当前筛选范围的数量或单币种消费为分母，总额为零时占比为零。排名显示筛选范围内最新记录的名称与颜色快照；同日以记录编号排序取值。

## 示例账本

首次没有保存文件时载入虚构示例并立即保存：2 个团体、3 位成员、4 个所属关系、3 种类型、1 个活动、5 笔记录，总数量 16。示例日期按创建时的 `Asia/Shanghai` 日历日及前两日生成，当天数量 10；不会固定为模板中的日期。页面不显示示例标记。

已有账本直接读取原资料，修改或删除示例后重启不会恢复。「载入手账示例」只允许空账本或未经修改的示例账本；空账本要求团体、成员、所属关系、活动、记录均为空，类型为空或恰为默认三种。仅归档资料不会让账本变空。首次导入可以替换未经修改的示例；任何已保存的示例编辑都会转为合并规则。

## JSON 字段

[ledger-template.json](../Templates/ledger-template.json) 是独立于时间表模板的可导入示例。使用 UTF-8，`schemaVersion` 必须为 `1`；以下六个数组必须存在，无资料时填写 `[]`。每个数组中的 `id` 必须唯一，编号和名称不能仅含空白。

| 数组 | 必填字段 | 可选字段 |
| --- | --- | --- |
| `groups` | `id`、`name` | `isArchived` |
| `members` | `id`、`name` | `avatarJPEGBase64`、`isArchived`、`isFavorite` |
| `memberships` | `id`、`memberID`、`groupID`、`color`、`prices` | `isArchived` |
| `products` | `id`、`name` | 无 |
| `events` | `id`、`name` | `date`、`city`、`venue`、`address` |
| `records` | 见下表 | 见下表 |

`memberships` 引用同一文件内的成员与团体，每对成员与团体只能有一个所属关系。`color` 使用六位 RGB，例如 `#F28AAF`。`prices` 可以为 `[]`；每项必填 `productID`、`currency`、`unitPriceMinor`，引用已有类型，同一所属关系内每个类型与币种组合只能出现一次。

`isArchived` 为可选布尔值，只有 `true` 表示归档；旧备份省略该字段仍可导入，版本号保持 `1`。有效所属关系还要求成员与团体均未归档。归档资料仍需合法，手工整理备份时必须保留历史消费引用的成员、团体及所属关系。

| `records` 字段 | 要求与含义 |
| --- | --- |
| `id` | 必填，唯一消费编号；新增消费使用新编号，推荐 UUID |
| `date` | 必填，有效公历日期，严格为 `yyyy-MM-dd`，例如 `2026-10-14` |
| `memberID`、`groupID`、`productID` | 必填，引用同一文件内的成员、团体、类型，并存在对应所属关系 |
| `quantity` | 必填，正整数数量 |
| `unitPriceMinor` | 必填，非负整数单价，以币种最小单位保存 |
| `currency` | 必填，下表中的大写币种代码 |
| `memberNameSnapshot`、`groupNameSnapshot`、`productNameSnapshot` | 必填，消费发生时的名称，不能仅含空白 |
| `colorSnapshot` | 必填，消费发生时的六位 RGB 代表色 |
| `eventID` | 可选，引用同一文件内 `events` 的编号 |
| `eventNameSnapshot`、`citySnapshot`、`venueSnapshot`、`addressSnapshot`、`note` | 可选，消费当时的活动、城市、场馆、地址及备注 |

消费日期保存为日历日，之后更换时区不会移动已有记录；活动日期可以与消费日期不同。头像字段存放 JPEG 的 Base64 数据，不是文件路径。

## 金额精度与限制

总额为 `quantity × unitPriceMinor`，金额使用整数运算。界面填写普通价格后转换为最小单位；超过允许小数位的输入会拒绝，不会静默四舍五入。建议使用数字及小数点，不填货币符号或千位分隔符；JSON 金额只能填整数。

| 币种 | 小数位 | 界面价格示例 | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`、`KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`、`HKD`、`USD`、`THB`、`IDR`、`MYR` | 2 | `100.00` | `10000` |

以上为 App 当前实现的精度，`IDR` 与 `TWD` 同样保留两位最小单位。单笔乘积、数量合计及各币种金额合计都检查整数溢出。JSON 文本和编码后的账本限 `20 × 1024 × 1024` 字节（20 MiB）；每张导入头像解码后限 `2 × 1024 × 1024` 字节（2 MiB），并校验 JPEG 结构。相册原图限 10 MiB，保存前缩至最长边 512 像素并转换为 JPEG。

## 导入、合并与备份

在手账顶部打开「手账管理」，切换至「备份」，选择一个或多个 JSON／文本文件，或粘贴 JSON 后校验预览，再确认导入。多文件先合并再预览；空文件、无资料文档、无效字段及冲突会阻止导入。文件必须自带全部引用资料，不能依赖当前账本补齐成员或团体。修改粘贴内容会使旧预览失效。

未经修改的示例账本会被有效导入替换；其他情况使用合并规则：

- 团体、成员、所属关系、类型与活动按 `id` 更新或新增；新文件未包含的旧资料保留。导入可更新归档标记。
- 消费按 `id` 去重。内容完全相同的记录重复导入不会重复计数；同编号内容不同则报错，取消整次导入。编辑消费请在 App 内操作，新消费使用新编号。
- 合并前后都校验整个文档，包括所属关系唯一性、引用关系、日期、快照、金额和大小；失败保留原账本。

导出包含整个账本、归档资料、历史快照、价格及头像。恢复是合并，不会撤销已有消费编辑；编辑后的记录与旧备份同编号内容不同会产生冲突。请妥善保存导出文件，以便迁移或留存资料。

## 管理、最爱成员与系统外观

- 0.4.0（build 10）的手账顶部与设置→数据管理入口为「手账管理」。页面提供「记录管理」「资料清理」「备份」；原有 JSON 导入、预览和完整导出仍在「备份」中。设置同时提供「日志管理」。
- 物贩记录可组合按日期范围、成员、团体、类型、币种、活动及搜索筛选，再逐条多选、全选当前结果或清除选择。更改任何筛选都会清空选择；无匹配结果时不能删除。确认前显示所选记录条数、总数量及分币种金额；取消不删除，只有明确确认才移除所选记录并更新统计。
- 「删除全部物贩记录」独立于当前筛选，需再次确认全账本的条数、数量与分币种金额。团体、成员、类型、活动目录及日志保留，可继续新增记录。
- 「资料清理」支持搜索、多选成员或团体。删除成员会归档其所有团体身份；删除团体只归档本团体及所属关系，兼任的其他身份保留。历史物贩、快照和统计保留，历史记录仍可编辑；取消确认不会归档，恢复目录可导入有效备份。
- 在「成员与类型」的成员编辑页单独设置或取消「最爱成员」。设置绑定成员编号，所有兼任身份共享；记录成员选择页顶部提供最爱专区，每个团体身份仍有独立颜色和价格，下方保留团体分组。新记录默认优先可用的最爱身份；关联已有成员也优先显示最爱，已归档成员或身份不进入最爱快捷选择。
- 成员的 `isFavorite` 是可选 Bool：只有 `true` 为最爱，`false`、省略或 `null` 均为未最爱。旧 JSON 仍可导入，`schemaVersion` 保持 `1`；完整备份保存最爱设置，按成员编号合并目录时同步更新。
- App 跟随系统浅色／深色外观，涵盖时间表、手账、日志、设置及所有编辑、选择、管理和备份页面；系统切换时界面同步变化，无需单独设置主题。成员代表色与历史快照继续保留。
