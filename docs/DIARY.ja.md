# 日記の使い方とバックアップ

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

日記はライブ、物販、遠征の体験を記録する機能です。原稿は端末内に保存され、編集を続けながら、公開用のテキストとしてコピーや書き出しができます。初回利用時に日記は登録されていません。テンプレートの架空の例は、自分でインポートした場合にのみ追加されます。

## 作成と整理

1. 3 番目の「日記」タブでプラスボタンを押し、タイトルと複数行の本文を入力します。入力した Markdown は保持されますが、エディターには Markdown の表示プレビューはありません。
2. 「要約とポイント」を入力します。一覧のカードには要約が優先して表示され、空の場合は本文の冒頭が表示されます。タグは最大 3 個表示されます。
3. タグはカンマ、読点、セミコロン、改行で区切ります。半角・全角の区切り文字に対応しています。前後の空白と `#`／`＃` を除去し、大文字・小文字を区別せず重複をまとめます。清音・濁音やアクセントの違いは別のタグとして保持されます。
4. イベント情報で既存の手帳イベントを選ぶと、名前、グレゴリオ暦の日付、都市、会場、住所が取り込まれます。有効な日付がない場合は現在選択中の日付が残ります。手入力や、編集画面から手帳イベントを追加することもできます。
5. 「下書き」または「整理済み」を選びます。端末内での整理と絞り込みに使う状態で、公開済みを意味しません。

イベント情報は日記ごとの独立したスナップショットです。手帳のイベントを変更・削除しても保存済みの日記は変わりません。イベントを選び直すとスナップショットが更新されます。手入力に戻してもイベント ID との関連が解除されるだけで、取り込んだ情報は消えません。日記は単独でも利用でき、会場と住所は手入力または手帳から取り込みます。

一覧はイベント日が新しい順にグループ化され、同じ日の中では最終更新時刻順に並びます。検索対象はタイトル、本文、要約、タグと、イベント名、日付、都市、会場、住所です。空白で区切った検索語はすべて一致する必要があり、別々の項目に一致しても構いません。すべて、下書き、整理済みで絞り込めます。

## 自動保存と削除

変更を止めてから約 0.5 秒後に自動保存されます。「完了」「閉じる」、バックグラウンドへの移行、編集画面からの離脱時には直ちに保存を試みます。失敗するとエラーと再試行ボタンが表示されます。「完了」「閉じる」で画面を離れるのは保存成功後のみで、書き込みに失敗しても保存済みデータは置き換わりません。

空のフォームを開くだけ、または日付や状態だけを変えても新しい日記は作成されません。タイトル、本文、要約、タグ、イベント名、都市、会場、住所のいずれかに実際の内容があると保存が始まります。保存済みの日記は文字を消しても残せます。すべての日記には常に有効なイベント日が必要です。

保存済み日記の編集画面の下部に削除ボタンがあり、確認が必要です。削除されるのは端末内の日記だけで、手帳イベント、購入記録、書き出したコピーは残ります。

## テキストの書き出しと完全バックアップ

「投稿の準備」では現在の変更を保存してからテキストを表示します。Markdown やプレーンテキストのコピー、`.md`／`.txt` の書き出し、iOS の共有シートを利用できます。テキストにはタイトル、イベント情報、タグ、要約、本文が含まれ、本文と要約の改行は保持されます。Markdown 書き出しではタイトルとイベント情報のインライン特殊文字をエスケープし、本文と要約は原文のまま残します。共有先とその後の操作は利用者が選択します。アプリは SNS アカウントに接続せず、自動投稿もしません。

日記タブ右上または 4 番目の「設定」タブから「日記の管理」を開いて「バックアップ」を選び、すべての日記を書き出すと、システムのファイル画面で完全な JSON を保存できます。JSON は ID、状態、タグ配列、イベントのスナップショット、作成・更新時刻を保持し、再インポートに適しています。`.md`／`.txt` は閲覧・共有用です。バックアップは自分で書き出して保管する必要があり、自動クラウドバックアップではありません。その後編集しても書き出し済みのファイルは更新されません。

## JSON 形式

[diary-template.json](../Templates/diary-template.json) は架空の例です。実際の記録に置き換え、追加する日記には新しい一意の ID を付けてください。ファイルは UTF-8 です。最上位には `schemaVersion`（整数 `1`）と `entries`（配列）が必須です。

| フィールド | 型 | 要件 |
| --- | --- | --- |
| `id` | 文字列 | 必須、空でなく一意であること。UUID を推奨します。 |
| `title` | 文字列 | 必須。下書きでは `""` でも可。 |
| `body` | 文字列 | 必須、本文全体。JSON の改行は `\n` と記述し、`""` でも可。 |
| `summary` | 文字列 | 必須、要約とポイント。`""` でも可。 |
| `tags` | 文字列配列 | 必須。タグがなければ `[]`。 |
| `status` | 文字列 | 必須。`draft` または `ready` のみ。 |
| `event` | オブジェクト | 必須。フィールドは下表を参照。 |
| `createdAt` | 文字列 | 必須、タイムゾーンを含む ISO 8601 の作成時刻。 |
| `updatedAt` | 文字列 | 必須、更新時刻。`createdAt` より前であってはなりません。 |

| `event` フィールド | 型 | 要件 |
| --- | --- | --- |
| `ledgerEventID` | 文字列または null | 任意。省略または `null` が可。文字列は空でないこと。手帳にイベントが残っている必要はありません。 |
| `name` | 文字列 | 必須、イベント名。`""` でも可。 |
| `date` | 文字列 | 必須、有効なグレゴリオ暦の日付。厳密に `yyyy-MM-dd`、例：`2026-10-14`。 |
| `city` | 文字列 | 必須、都市。`""` でも可。 |
| `venue` | 文字列 | 必須、会場。`""` でも可。 |
| `address` | 文字列 | 必須、住所全体。`""` でも可。 |

`event.date` は年月日で、タイムゾーンや時分秒を含みません。作成・更新時刻は絶対時刻を表し、`2026-01-01T00:00:00.000Z` のようにミリ秒精度で書き出されます。インポートでは `2026-01-01T09:00:00.000+09:00` のような明示的な UTC オフセットも利用できます。`Z` やオフセットは省略できません。後日レポートを書く場合、イベント日は日記の作成時刻より前でも構いません。日記バックアップにメンバー、グループ、手帳のバックアップは不要です。

## インポートと競合

「日記の管理」の「バックアップ」で UTF-8 の JSON ファイルを 1 つまたは複数選ぶか、JSON を貼り付けて確認・プレビューします。新規と既存の件数が表示され、確認後にのみ書き込まれます。

- ID とすべての内容が同じ日記は重複としてまとめられます。作成・更新時刻はミリ秒精度で比較します。
- 同じ ID で本文、要約、タグ、状態、イベント情報、タイムスタンプなどが異なる場合、インポート全体を中止し、元のデータを保持します。既存の日記はアプリ内で編集し、別の版を残す場合は新しい ID を使用してください。
- インポートは新しい日記の追加のみです。ファイルに含まれない既存の日記は残ります。選択した複数ファイル間にも同じ競合ルールが適用されます。
- 各入力と統合後のデータの上限は 20 MiB（`20 * 1024 * 1024` バイト）です。手動編集も同じ制限を受けます。
- ID の重複、必須項目の欠落、型の誤り、無効な状態、日付、タイムスタンプ、UTF-8 はエラーとなります。フィールドのエラーには位置が表示され、検証に失敗すると書き込まれません。

インポート画面では空の日記集合を拒否します。内部保存と書き出しでは `entries: []` が許可され、現在日記がないことを表します。

## 端末内データと言語

日記は Application Support 内の `OshicueKit/diary.json` に独立してアトミックに保存され、再起動時に読み込まれます。元のファイルが破損していた場合、初めて正常に置き換える前に、同じディレクトリに `diary.recovery-<UUID>.json` の復旧用コピーが保存されます。この仕組みは利用者のバックアップに代わるものではありません。

設定の言語選択はタイムテーブル、手帳、日記、設定に共通で適用されます。日付表示は言語に合わせて変わりますが、本文、イベント名、住所などの入力内容はそのまま残ります。

## 日記の管理とシステムの外観

- 0.4.0（build 10）では、日記右上または設定→データ管理から「日記の管理」を開きます。「記録の管理」と「バックアップ」があり、JSON の読み込み、プレビュー、全日記の書き出しは「バックアップ」に残ります。
- 状態、イベントの日付範囲、検索を組み合わせ、各日記の複数選択、現在の結果の全選択、選択解除ができます。条件変更で選択を解除します。削除前に件数と本文・要約の削除を確認し、キャンセルでは削除しません。確認後は選択した日記のみ削除し、他の日記、手帳、タイムテーブルは残ります。削除結果は端末に保存します。
- 日記一覧、編集、公開準備、管理、バックアップ、設定はシステムのライト／ダーク外観に即時対応します。保存済み本文とイベントのスナップショットは元の内容を保持します。
