# 手帳用法同資料格式

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

手帳用月曆記錄物販消費，管理團體、成員、所屬關係、代表色同預設價格，並統計數量同消費排名。資料儲存喺本機，手帳備份同時間表、日誌備份分開。

## 開始使用

1. 喺「成員同類型」新增團體同成員。同一成員兼任多個團體時，使用「連結已有成員（兼任）」新增所屬關係，沿用同一個成員編號；同名但編號唔同嘅成員唔會自動合併。
2. 為各所屬關係分別設定代表色同預設單價。預設類型有拍立得、WIDE 拍立得、手機合照，亦可以新增類型；同一類型可設定唔同幣種價格。成員名稱同頭像由各團體共用。
3. 撳「＋」，選擇日期、成員所屬團體、類型、數量、幣種同實際單價。切換成員身份、類型或幣種會重新帶入相應預設價格；冇預設價格時要填寫單價。數量要係正整數，單價可以係零。
4. 活動、城市、場地、地址同備註都可以唔填。可以建立手帳活動，或者喺時間表揀活動同場地，再複製成手帳活動；之後改動時間表唔會自動同步到手帳。
5. 月曆數字表示當日物販總數量，唔係紀錄筆數。月份卡片顯示當月數量同各幣種消費；選定日期後可查看成員分團體彙總同逐筆紀錄。

數量代表類型嘅份數：照片按張計，新增票券類可按券計。

## 編輯、刪除同歷史快照

撳日期下方嘅成員卡片：只有一筆消費時直接開啟編輯；有多筆時先選擇紀錄。亦可以展開逐筆紀錄進入編輯。表格帶入原有日期、身份、類型、數量、單價同選填資訊，儲存只更新該筆紀錄。編輯頁嘅「刪除呢筆物販」要確認，刪除後數量同金額隨之扣除。

喺「成員同類型」撳成員編輯資料；團體標題旁嘅鉛筆開啟團體編輯。刪除成員或團體都要確認：

- 刪除成員：封存呢位成員同佢喺所有團體中嘅所屬關係。
- 刪除團體：封存團體同其所屬關係；兼任其他團體嘅成員仍然可以使用。

封存資料留喺備份中，已有消費、名稱、代表色、單價同統計都保留。新紀錄同改選身份只可以用有效所屬關係；歷史紀錄仍然可以保留原已刪除身份編輯，選擇器會標示「已刪除」。資料編輯頁冇還原入口；匯入含同編號有效資料嘅備份可還原目錄資料，仍然要通過完整合併驗證。

修改目錄名稱、代表色或預設價格唔會改寫已儲存消費。編輯消費時，保留同一身份會保留成員、團體同顏色快照；保留同一類型會保留類型名稱快照。改選身份或類型時重新取得相應快照；實際單價同活動資訊依表格儲存。儲存之前先驗證完整帳本，再一次過寫入本機；失敗唔會套用部分修改。

## 統計

統計支援日、月、年同生涯範圍，可以按類型同團體篩選，按成員合計、成員分團體或團體排名。成員人數按篩選後唔同嘅 `memberID` 計算。已封存團體仍然可以用於歷史統計篩選。

數量排名可以合計所有幣種嘅份數，消費排名要選擇一種幣種；金額唔會混加或自動換匯。彙總按類型列出數量同分幣種金額。排名用競賽名次，例如 `1、1、3`；同分按編號穩定排序，占比以而家篩選範圍嘅數量或單幣種消費為分母，總額係零時占比係零。排名顯示篩選範圍內最新紀錄嘅名稱同顏色快照；同日按紀錄編號排序取值。

## 示範帳本

首次冇儲存檔案時載入虛構示範並即時儲存：2 個團體、3 位成員、4 個所屬關係、3 種類型、1 個活動、5 筆紀錄，總數量 16。示範日期依建立時嘅 `Asia/Shanghai` 月曆日同前兩日產生，當日數量 10；唔會固定為範本入面嘅日期。頁面唔顯示示範標記。

已有帳本直接讀取原資料，修改或刪除示範後重新開啟唔會還原。「載入手帳示範」只容許空帳本或未修改嘅示範帳本；空帳本要冇團體、成員、所屬關係、活動同紀錄，類型係空或同預設三種完全一樣。只封存資料唔會令帳本變空。首次匯入可以取代未修改嘅示範；只要儲存過示範嘅修改，之後匯入就會用合併規則。

## JSON 欄位

[ledger-template.json](../Templates/ledger-template.json) 係獨立於時間表範本嘅可匯入示範。使用 UTF-8，`schemaVersion` 一定要係 `1`；以下六個陣列一定要存在，冇資料時填 `[]`。各陣列內嘅 `id` 要唯一，編號同名稱唔可以只含空白。

| 陣列 | 必填欄位 | 選填欄位 |
| --- | --- | --- |
| `groups` | `id`、`name` | `isArchived` |
| `members` | `id`、`name` | `avatarJPEGBase64`、`isArchived`、`isFavorite` |
| `memberships` | `id`、`memberID`、`groupID`、`color`、`prices` | `isArchived` |
| `products` | `id`、`name` | 無 |
| `events` | `id`、`name` | `date`、`city`、`venue`、`address` |
| `records` | 見下表 | 見下表 |

`memberships` 引用同一檔案內嘅成員同團體，每對成員同團體只可以有一個所屬關係。`color` 使用六位 RGB，例如 `#F28AAF`。`prices` 可以係 `[]`；每項必填 `productID`、`currency`、`unitPriceMinor`，引用已有類型，同一所屬關係內各類型同幣種組合只能出現一次。

`isArchived` 係選填布林值，只有 `true` 表示封存；舊備份省略呢個欄位仍然可以匯入，版本號維持 `1`。有效所屬關係亦要求成員同團體都未封存。封存資料仍然要合法，手動整理備份時要保留歷史消費引用嘅成員、團體同所屬關係。

| `records` 欄位 | 要求同含義 |
| --- | --- |
| `id` | 必填，唯一消費編號；新增消費使用新編號，建議 UUID |
| `date` | 必填，有效西曆日期，嚴格使用 `yyyy-MM-dd`，例如 `2026-10-14` |
| `memberID`、`groupID`、`productID` | 必填，引用同一檔案嘅成員、團體、類型，且存在相應所屬關係 |
| `quantity` | 必填，正整數數量 |
| `unitPriceMinor` | 必填，非負整數單價，以幣種最小單位儲存 |
| `currency` | 必填，下表中嘅大寫幣種代碼 |
| `memberNameSnapshot`、`groupNameSnapshot`、`productNameSnapshot` | 必填，消費當時嘅名稱，唔可以只含空白 |
| `colorSnapshot` | 必填，消費當時嘅六位 RGB 代表色 |
| `eventID` | 選填，引用同一檔案內 `events` 嘅編號 |
| `eventNameSnapshot`、`citySnapshot`、`venueSnapshot`、`addressSnapshot`、`note` | 選填，消費當時嘅活動、城市、場地、地址同備註 |

消費日期以月曆日儲存，之後更換時區唔會移動已有紀錄；活動日期可同消費日期唔同。頭像欄位存放 JPEG 嘅 Base64 資料，唔係檔案路徑。

## 金額精度同限制

總額係 `quantity × unitPriceMinor`，金額使用整數運算。畫面填寫一般價格後轉換為最小單位；超過允許小數位嘅輸入會被拒絕，唔會默默四捨五入。建議用數字同小數點，唔好填貨幣符號或千位分隔符號；JSON 金額只可以填整數。

| 幣種 | 小數位 | 畫面價格示範 | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`、`KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`、`HKD`、`USD`、`THB`、`IDR`、`MYR` | 2 | `100.00` | `10000` |

以上係 App 而家採用嘅精度，`IDR` 同 `TWD` 同樣保留兩位最小單位。單筆乘積、數量合計同各幣種金額合計都檢查整數溢位。JSON 文字同編碼後帳本上限係 `20 × 1024 × 1024` 字節（20 MiB）；每張匯入頭像解碼後上限係 `2 × 1024 × 1024` 字節（2 MiB），並檢查 JPEG 結構。相簿原圖上限 10 MiB，儲存前縮至最長邊 512 像素並轉為 JPEG。

## 匯入、合併同備份

喺手帳頂部開啟「手帳管理」，轉去「備份」，選擇一個或多個 JSON／文字檔，或貼上 JSON 驗證預覽後確認匯入。多檔先合併再預覽；空檔、無資料文件、無效欄位同衝突都會阻止匯入。檔案要自帶全部引用資料，唔可以依賴而家帳本補齊成員或團體。修改貼上嘅內容會使舊預覽失效。

未修改嘅示範帳本會被有效匯入取代；其他情況用合併規則：

- 團體、成員、所屬關係、類型同活動按 `id` 更新或新增；新檔未包含嘅舊資料保留。匯入可更新封存標記。
- 消費按 `id` 去除重複。完全相同嘅紀錄再次匯入唔會重複計數；同編號內容唔同會報錯，取消整次匯入。編輯消費請喺 App 入面操作，新消費使用新編號。
- 合併前後都驗證完整文件，包含所屬關係唯一性、引用關係、日期、快照、金額同大小；失敗保留原帳本。

匯出包含完整帳本、封存資料、歷史快照、價格同頭像。還原用合併方式，唔會撤銷已有消費編輯；編輯後紀錄同舊備份同編號內容唔同會產生衝突。請好好保存匯出檔案，方便轉移或者保留資料。

## 管理、最愛成員同系統外觀

- 0.4.0（build 10）嘅手帳頂部同設定→資料管理入口係「手帳管理」。頁面有「記錄管理」「資料清理」「備份」；原有 JSON 匯入、預覽同完整匯出仍然喺「備份」內。設定亦有「日誌管理」。
- 物販紀錄可以組合日期範圍、成員、團體、類型、貨幣、活動同搜尋篩選，再逐筆多選、全選目前結果或者清除選取。改任何篩選都會清空選取；冇符合結果就唔可以刪除。確認前顯示所選紀錄條數、總數量同各貨幣金額；取消唔會刪除，明確確認先移除所選紀錄同更新統計。
- 「刪除全部物販紀錄」唔受目前篩選影響，要再次確認完整帳本嘅條數、數量同各貨幣金額。團體、成員、類型、活動目錄同日誌保留，可以繼續新增紀錄。
- 「資料清理」支援搜尋、多選成員或者團體。刪除成員會封存佢所有團體身份；刪除團體只封存本團體同所屬關係，兼任嘅其他身份保留。歷史物販、快照同統計保留，歷史紀錄仍然可以編輯；取消確認唔會封存，可以匯入有效備份還原目錄。
- 喺「成員與類型」嘅成員編輯頁單獨設定或者取消「最愛成員」。設定跟成員編號，所有兼任身份共用；紀錄成員選擇頁頂部有最愛專區，每個團體身份仍然有獨立顏色同價格，下方保留團體分組。新紀錄預設優先用有效嘅最愛身份；關聯已有成員亦優先顯示最愛，已封存成員或者身份唔會出現喺最愛快捷選擇。
- 成員嘅 `isFavorite` 係可選 Bool：只有 `true` 係最愛，`false`、省略或者 `null` 都係未最愛。舊 JSON 仍然可以匯入，`schemaVersion` 保持 `1`；完整備份會保存最愛設定，按成員編號合併目錄時一併更新。
- App 跟系統淺色／深色外觀，包括時間表、手帳、日誌、設定同所有編輯、選擇、管理及備份頁面；系統切換時介面同步改變，唔使另外設定主題。成員代表色同歷史快照繼續保留。
