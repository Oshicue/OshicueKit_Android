# 일기 사용과 백업

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

일기는 공연, 굿즈 판매 행사, 원정 경험을 기록하는 기능입니다. 원고는 기기에 저장되며 계속 편집한 뒤 게시용 텍스트로 복사하거나 내보낼 수 있습니다. 처음 사용할 때 미리 등록된 일기는 없습니다. 템플릿의 가상 예시는 직접 가져와야 추가됩니다.

## 작성과 정리

1. 세 번째 “일기” 탭에서 더하기 버튼을 누르고 제목과 여러 줄 본문을 입력합니다. 입력한 Markdown은 유지되지만 편집기에서 Markdown 렌더링 미리 보기는 제공하지 않습니다.
2. 요약과 핵심 내용을 입력합니다. 목록 카드는 요약을 먼저 표시하고, 요약이 비어 있으면 본문 앞부분을 표시합니다. 태그는 최대 3개 표시됩니다.
3. 태그는 쉼표, 모점, 세미콜론, 줄바꿈으로 구분하며 반각과 전각 구분자를 지원합니다. 앞뒤 공백과 `#`／`＃`를 제거하고 대소문자를 무시하여 중복을 정리합니다. 일본어 청음과 탁음, 서로 다른 악센트는 별도 태그로 유지합니다.
4. 행사 정보에서 기존 수첩 행사를 선택하면 이름, 그레고리력 날짜, 도시, 장소, 주소를 가져옵니다. 유효한 날짜가 없으면 현재 선택한 날짜를 유지합니다. 직접 입력하거나 편집 화면에서 수첩 행사를 추가할 수도 있습니다.
5. “초안” 또는 “정리 완료”를 선택합니다. 기기 내 정리와 필터에 사용하는 상태이며 게시 완료를 뜻하지 않습니다.

행사 정보는 해당 일기에 저장된 독립적인 스냅샷입니다. 수첩 행사를 수정하거나 삭제해도 저장된 일기는 바뀌지 않습니다. 행사를 다시 선택해야 스냅샷이 갱신됩니다. 수동 입력으로 전환하면 행사 ID 연결만 해제되고 가져온 정보는 유지됩니다. 일기는 독립적으로 사용할 수 있으며 장소와 주소는 직접 입력하거나 수첩에서 가져옵니다.

목록은 행사 날짜가 최신인 순서로 묶고, 같은 날짜 안에서는 최근 수정 시각 순으로 정렬합니다. 검색 대상은 제목, 본문, 요약, 태그와 행사 이름, 날짜, 도시, 장소, 주소입니다. 공백으로 구분한 검색어가 모두 일치해야 하며 서로 다른 필드에 있어도 됩니다. 전체, 초안, 정리 완료로 필터링할 수 있습니다.

## 자동 저장과 삭제

수정을 멈춘 뒤 약 0.5초 후 자동 저장합니다. “완료”나 “닫기”를 누르거나, 앱이 백그라운드로 이동하거나, 편집 화면을 벗어날 때 즉시 저장을 시도합니다. 저장에 실패하면 오류와 재시도 버튼을 표시합니다. “완료”와 “닫기”는 저장이 성공해야 화면을 닫으며, 쓰기에 실패해도 저장된 데이터는 덮어쓰지 않습니다.

빈 양식을 열거나 날짜 또는 상태만 바꾸면 새 일기를 만들지 않습니다. 제목, 본문, 요약, 태그, 행사 이름, 도시, 장소, 주소 중 하나에 실제 내용이 있으면 저장을 시작합니다. 이미 저장된 일기는 텍스트를 지워도 유지할 수 있습니다. 모든 일기에는 항상 유효한 행사 날짜가 필요합니다.

저장된 일기의 편집 화면 아래에 삭제 버튼이 있으며 확인이 필요합니다. 삭제는 기기 내 일기만 제거합니다. 수첩 행사, 구매 기록, 이미 내보낸 사본은 삭제하지 않습니다.

## 텍스트 내보내기와 전체 백업

게시 준비 기능은 현재 변경 사항을 먼저 저장한 뒤 텍스트를 표시합니다. Markdown 또는 일반 텍스트를 복사하거나 `.md`／`.txt`로 내보내고, iOS 공유 시트를 열 수 있습니다. 텍스트에는 제목, 행사 정보, 태그, 요약, 본문이 포함되며 본문과 요약의 줄바꿈은 유지됩니다. Markdown 내보내기는 제목과 행사 정보의 인라인 특수 문자를 이스케이프하고 본문과 요약은 원문을 유지합니다. 공유 대상과 이후 작업은 사용자가 선택하며, 앱은 소셜 계정에 연결하거나 자동 게시하지 않습니다.

일기 탭 오른쪽 위 또는 네 번째 “설정” 탭에서 “일기 관리”를 열고 “백업”을 선택합니다. 전체 일기 내보내기는 시스템 파일 선택 화면을 통해 완전한 JSON을 저장합니다. JSON은 ID, 상태, 태그 배열, 행사 스냅샷, 생성 및 수정 시각을 보존하므로 다시 가져오기에 적합합니다. `.md`／`.txt`는 읽기와 공유용입니다. 백업은 직접 내보내고 보관해야 합니다. 자동 클라우드 백업이 아니며, 편집을 계속해도 내보낸 파일은 갱신되지 않습니다.

## JSON 형식

[diary-template.json](../Templates/diary-template.json)은 가상 예시입니다. 실제 기록으로 바꾸고 새 일기에는 새로운 고유 ID를 부여하세요. 파일 인코딩은 UTF-8입니다. 최상위 필수 필드는 `schemaVersion`(정수 `1`)과 `entries`(배열)입니다.

| 필드 | 유형 | 요구 사항 |
| --- | --- | --- |
| `id` | 문자열 | 필수, 비어 있지 않고 고유해야 합니다. UUID를 권장합니다. |
| `title` | 문자열 | 필수, 초안은 `""` 허용. |
| `body` | 문자열 | 필수, 전체 본문. JSON 줄바꿈은 `\n`으로 쓰며 `""` 허용. |
| `summary` | 문자열 | 필수, 요약과 핵심 내용. `""` 허용. |
| `tags` | 문자열 배열 | 필수, 태그가 없으면 `[]`. |
| `status` | 문자열 | 필수, `draft` 또는 `ready`만 허용. |
| `event` | 객체 | 필수, 아래 표 참조. |
| `createdAt` | 문자열 | 필수, 시간대가 포함된 ISO 8601 생성 시각. |
| `updatedAt` | 문자열 | 필수, 수정 시각. `createdAt`보다 이르면 안 됩니다. |

| `event` 필드 | 유형 | 요구 사항 |
| --- | --- | --- |
| `ledgerEventID` | 문자열 또는 null | 선택 사항, 생략하거나 `null` 허용. 문자열은 비어 있으면 안 되며 행사가 수첩에 남아 있을 필요는 없습니다. |
| `name` | 문자열 | 필수, 행사 이름. `""` 허용. |
| `date` | 문자열 | 필수, 유효한 그레고리력 날짜. 정확히 `yyyy-MM-dd` 형식이며 예: `2026-10-14`. |
| `city` | 문자열 | 필수, 도시. `""` 허용. |
| `venue` | 문자열 | 필수, 장소. `""` 허용. |
| `address` | 문자열 | 필수, 전체 주소. `""` 허용. |

`event.date`는 연월일이며 시간대나 시분초가 없습니다. 생성 및 수정 시각은 절대 시각이며 `2026-01-01T00:00:00.000Z`처럼 밀리초 정밀도로 내보냅니다. 가져올 때 `2026-01-01T09:00:00.000+09:00`과 같이 명시적인 UTC 오프셋도 허용합니다. `Z`나 오프셋을 생략하면 안 됩니다. 나중에 후기를 쓰는 경우 행사 날짜가 일기 생성 시각보다 빨라도 됩니다. 일기 백업은 멤버, 그룹, 수첩 백업을 요구하지 않습니다.

## 가져오기와 충돌

“일기 관리”의 “백업”에서 UTF-8 JSON 파일을 하나 이상 선택하거나 JSON을 붙여 넣고 검사 및 미리 보기를 실행합니다. 새 일기와 기존 일기의 수가 표시되며 확인 후에만 저장됩니다.

- 같은 ID에 모든 내용이 같은 일기는 중복 제거합니다. 생성 및 수정 시각은 밀리초 정밀도로 비교합니다.
- 같은 ID에서 본문, 요약, 태그, 상태, 행사 정보, 타임스탬프 등이 다르면 전체 가져오기를 중단하고 원래 데이터를 유지합니다. 기존 일기는 앱에서 수정하고 다른 버전을 보관하려면 새 ID를 사용하세요.
- 가져오기는 새 일기만 추가하며 파일에 없는 기존 일기는 유지합니다. 선택한 여러 파일 사이에도 같은 충돌 규칙을 적용합니다.
- 각 입력과 병합된 데이터의 최대 크기는 20 MiB(`20 * 1024 * 1024`바이트)입니다. 수동 편집에도 같은 제한이 있습니다.
- 중복 ID, 누락 필드, 잘못된 유형, 유효하지 않은 상태, 날짜, 타임스탬프, UTF-8은 오류를 표시합니다. 필드 오류에는 위치를 표시하며 검증에 실패하면 저장하지 않습니다.

가져오기 화면은 빈 일기 모음을 거부합니다. 내부 저장과 내보내기는 `entries: []`를 허용하며 현재 일기가 없다는 뜻입니다.

## 기기 내 데이터와 언어

일기는 Application Support의 `OshicueKit/diary.json`에 독립적으로 원자적 저장하며 재시작할 때 읽습니다. 원본 파일이 손상되면 처음 성공적으로 교체하기 전에 같은 폴더에 `diary.recovery-<UUID>.json` 복구 사본을 보관합니다. 이 기능은 사용자의 백업을 대신하지 않습니다.

설정의 언어 선택은 시간표, 수첩, 일기, 설정에 함께 적용됩니다. 날짜 표시는 언어에 맞춰 바뀌지만 본문, 행사 이름, 주소 등 사용자가 입력한 내용은 유지됩니다.

## 일기 관리와 시스템 화면 모드

- 0.4.0(build 10)에서는 일기 오른쪽 위 또는 설정→데이터 관리에서 “일기 관리”를 엽니다. “기록 관리”와 “백업”이 있으며 JSON 가져오기, 미리 보기, 전체 일기 내보내기는 “백업”에 유지됩니다.
- 상태, 행사 날짜 범위, 검색을 조합하여 개별 다중 선택, 현재 결과 전체 선택, 선택 해제를 할 수 있습니다. 조건 변경 시 선택이 해제됩니다. 삭제 전에 일기 수와 본문·요약 삭제 범위를 확인하며 취소하면 유지합니다. 확인하면 선택한 일기만 삭제하고 다른 일기, 수첩, 시간표는 유지하며 결과를 기기에 저장합니다.
- 일기 목록, 편집기, 게시 준비, 관리, 백업, 설정은 시스템 밝은 모드와 어두운 모드를 즉시 따릅니다. 저장된 본문과 행사 스냅샷의 내용은 유지합니다.
