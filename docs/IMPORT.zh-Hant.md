# 時間表 JSON 匯入

[简体中文](IMPORT.zh-CN.md) | [繁體中文](IMPORT.zh-Hant.md) | [繁體粵語](IMPORT.zh-HK.md) | [English](IMPORT.en.md) | [日本語](IMPORT.ja.md) | [한국어](IMPORT.ko.md) | [ไทย](IMPORT.th.md) | [Bahasa Indonesia](IMPORT.id.md) | [Bahasa Melayu](IMPORT.ms.md)

使用 UTF-8 JSON。開啟時間表的匯入入口，可貼上全文或選取一個／多個 `.json`、純文字檔案。驗證成功後會顯示活動及場次數量，按下確認才套用。修改預覽中的文字後，需要重新驗證。

## 更新與收藏

首次啟動會產生並儲存兩份虛構日程，以啟動時的東京當地整點為基準，並包含隔日排程；初始收藏前兩個團體。標題不顯示範例標記，之後啟動會讀取已儲存的資料。首次正式匯入會取代仍處於範例狀態的日程，並清除範例收藏。之後的匯入保留其他活動，相同活動 `id` 則取代該活動的完整內容，更新時應提供完整活動，而非部分場次。

團體 `id` 是跨活動共用的收藏身分。保留 ID 可在改名後延續收藏；連點兩下 LIVE 或物販方塊會切換該團體收藏。我的日程依所選活動和日期合併顯示收藏團體的 LIVE、物販。時間重疊是合法排程，會並排顯示並提示衝突；提示只比較時間，不評估交通或趕場可行性。

## 欄位

| 位置 | 欄位 | 規則 |
| --- | --- | --- |
| 最上層 | `schemaVersion` | 必填整數，固定為 `1`。 |
| 最上層 | `events` | 必填活動陣列。匯入入口要求至少一個活動，整批至少一個場次。 |
| 活動 | `id`, `name`, `city` | 必填非空字串。活動 ID 在整批內須唯一。 |
| 活動 | `timeZone` | 必填有效 IANA 時區，例如 `Asia/Tokyo`。 |
| 活動 | `venues`, `artists`, `sessions` | 必填陣列；允許個別活動沒有場次。 |
| 場館 | `id`, `name`, `color` | 非空 ID、名稱；顏色必須為 `#RRGGBB`，例如 `#78C9EB`。 |
| 團體 | `id`, `name` | 必填非空字串。團體 ID 應跨活動維持穩定。 |
| 場次 | `id`, `artistID`, `venueID` | 非空場次 ID；參照本活動宣告的團體和場館。 |
| 場次 | `kind` | 只能是 `live` 或 `goods`。 |
| 場次 | `startsAt`, `endsAt` | 完整 ISO 8601 日期時間，包含秒及 `Z` 或明確偏移；結束必須晚於開始。 |
| 場次 | `area`, `notes` | 選填字串，可省略或為 `null`。 |

場館、團體、場次 ID 分別在所屬活動內須唯一。必填字串不能只有空白。JSON 不支援註解或尾隨逗號。可輸入未知欄位，但 App 不會顯示，重新編碼時也不會保留。

## 驗證與批次匯入

錯誤會顯示欄位路徑，例如 `$.events[0].sessions[2].endsAt`。版本、型別、日期、時區、顏色、重複 ID、無效參照或時長錯誤，都會中止整份內容的驗證。多個檔案先合併後統一驗證，跨檔案重複活動 ID 也會失敗；任何檔案失敗都不會部分匯入。匯入入口不能套用空活動陣列或完全沒有場次的整批內容；底層允許 `events: []`，用於儲存刪空後的內部狀態。

## 時區與跨午夜

接受 `2026-10-14T12:00:00+09:00`、`2026-10-14T03:00:00Z` 和小數秒。`12:00`、缺少秒數或時區的值均無效。偏移決定絕對時刻，活動 `timeZone` 決定當地日期；應依場次實際時區填寫。日光節約時間重複小時的 `2026-11-01T01:30:00-04:00` 與 `2026-11-01T01:30:00-05:00` 是兩個時刻。

跨午夜需填寫隔日結束日期：`2026-10-14T23:40:00+09:00` → `2026-10-15T00:20:00+09:00`。場次會出現在涵蓋的兩個日期，圖塊裁切至當天；正好在 `00:00:00` 結束不會增加空白日期。沒有人工設定的最長時長限制。

同時選取不同時區活動時，目前介面統一採用所選活動中排列第一個的活動時區，顯示日期、時間和詳情，並在篩選列標明時區。要查看某活動自己的當地時間，請單獨選取該活動。現在時間線使用真實系統時間，固定範例日期不一定是今天。

## 編輯範本

複製文末連結中的時間表範本，保留 `schemaVersion` 和 `events`，填入穩定 ID，再複製場次修改參照、類型和時間。範本中的活動、團體及排程均為虛構內容；範本不會自動匯入。
