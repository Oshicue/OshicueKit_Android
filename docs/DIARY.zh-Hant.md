# 日誌使用與備份

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

日誌用來記錄演出、物販及遠征經驗。原稿儲存在本機，可持續編輯，再複製或匯出為發布用文字。首次使用沒有預設日誌；範本中的虛構範例需要主動匯入。

## 新增與整理

1. 在第三個「日誌」頁點選加號，填寫標題和多行內文。內文可保留自行輸入的 Markdown，編輯器不提供 Markdown 渲染預覽。
2. 填寫「摘要與重點」。清單卡片優先顯示摘要，摘要空白時顯示內文開頭，並最多顯示三個標籤。
3. 標籤以逗號、頓號、分號或換行分隔，支援半形及全形分隔符號。自動去除頭尾空白與 `#`／`＃`，忽略大小寫去除重複；日文清濁音和不同重音仍保留為不同標籤。
4. 在「活動資料」選擇既有手帳活動，帶入名稱、公曆日期、城市、場館及地址；缺少有效日期時保留目前選擇的日期。也可手動填寫，或在編輯頁新增手帳活動。
5. 選擇「草稿」或「已整理」；狀態僅用於本機整理與篩選，不表示已發布。

活動資料是日誌自己的快照。修改或刪除手帳活動不會改寫已儲存日誌；再次選入活動時才更新快照。切回手動填寫只解除活動編號關聯，不清空已帶入資料。日誌可以獨立使用，場館及地址由使用者填寫或從手帳帶入。

清單依活動日期由近到遠分組，同一天依最近修改時間排序。搜尋涵蓋標題、內文、摘要、標籤及活動名稱、日期、城市、場館、地址；多個空白分隔的詞必須全部符合，可分別出現在不同欄位。可篩選全部、草稿、已整理。

## 自動儲存與刪除

停止修改約 0.5 秒後自動儲存。點選「完成」「關閉」、進入背景或離開編輯頁時會立即嘗試儲存。儲存失敗時顯示錯誤與重試入口；「完成」「關閉」僅在儲存成功後退出，寫入失敗不會取代已儲存資料。

僅開啟空白表單、只更改日期或狀態不會建立新日誌；標題、內文、摘要、標籤或活動名稱、城市、場館、地址中有實際內容時才開始儲存。已儲存日誌清空文字後仍可保留。每篇日誌始終需要有效活動日期。

已儲存日誌的編輯頁底部有「刪除日誌」，操作需要確認。刪除只移除本機日誌，不刪除手帳活動、消費紀錄或已匯出的副本。

## 文字匯出與完整備份

「準備發布」會先儲存目前修改，再顯示文字。可複製 Markdown 或純文字、匯出 `.md`／`.txt`，或開啟 iOS 系統分享面板。文字包含標題、活動資料、標籤、摘要及內文；內文、摘要保留原有換行。Markdown 匯出會逸出標題及活動資料中的行內特殊字元，內文與摘要保持原文。分享對象與後續操作由使用者選擇，App 不連接社群帳號或自動發布。

從日誌頁右上角或第四個「設定」頁開啟「日誌管理」，切換至「備份」，「匯出全部日誌」透過系統檔案面板儲存完整 JSON。JSON 保留編號、狀態、標籤陣列、活動快照及建立和修改時間，適合再次匯入；`.md`／`.txt` 用於閱讀及分享。備份需要主動匯出與保管，不是自動雲端備份；繼續編輯不會更新已匯出的檔案。

## JSON 格式

[diary-template.json](../Templates/diary-template.json) 是虛構範例。請替換為實際紀錄，為新增日誌分配新的唯一編號；檔案使用 UTF-8。最外層必填 `schemaVersion`（整數 `1`）及 `entries`（陣列）。

| 欄位 | 型別 | 要求 |
| --- | --- | --- |
| `id` | 字串 | 必填、非空且唯一，建議使用 UUID。 |
| `title` | 字串 | 必填，草稿可為 `""`。 |
| `body` | 字串 | 必填，完整內文；JSON 換行寫為 `\n`，可為 `""`。 |
| `summary` | 字串 | 必填，摘要與重點，可為 `""`。 |
| `tags` | 字串陣列 | 必填，沒有標籤時寫 `[]`。 |
| `status` | 字串 | 必填，只能為 `draft` 或 `ready`。 |
| `event` | 物件 | 必填，欄位見下表。 |
| `createdAt` | 字串 | 必填，包含時區的 ISO 8601 建立時間。 |
| `updatedAt` | 字串 | 必填，修改時間，不得早於 `createdAt`。 |

| `event` 欄位 | 型別 | 要求 |
| --- | --- | --- |
| `ledgerEventID` | 字串或 null | 選填，可省略或為 `null`；字串須非空，不要求活動仍在手帳中。 |
| `name` | 字串 | 必填，活動名稱，可為 `""`。 |
| `date` | 字串 | 必填，有效公曆日期，嚴格使用 `yyyy-MM-dd`，如 `2026-10-14`。 |
| `city` | 字串 | 必填，城市，可為 `""`。 |
| `venue` | 字串 | 必填，場館，可為 `""`。 |
| `address` | 字串 | 必填，完整地址，可為 `""`。 |

`event.date` 是年月日，沒有時區或時分秒。建立及修改時間是絕對時間，匯出為毫秒精度，例如 `2026-01-01T00:00:00.000Z`。匯入也接受明確 UTC 位移，例如 `2026-01-01T09:00:00.000+09:00`；不能省略 `Z` 或位移。活動日期可早於補寫日誌的建立時間。日誌備份不要求成員、團體或手帳備份。

## 匯入與衝突

在「日誌管理」的「備份」中選擇一個或多個 UTF-8 JSON 檔案，或貼上 JSON 後點選「檢查並預覽」。預覽列出新增和已存在數量，確認後才寫入。

- 相同編號且所有內容相同的日誌會去除重複；建立、修改時間以毫秒精度比較。
- 相同編號內容不同，包括內文、摘要、標籤、狀態、活動資料或時間戳記不同，整次匯入停止，原資料保留。修改舊日誌請在 App 內編輯；保留另一版本請使用新編號。
- 匯入只增加新日誌，原資料中未出現在檔案中的日誌繼續保留。多個選取檔案之間也採用相同衝突規則。
- 每份輸入及合併後資料的上限為 20 MiB（`20 * 1024 * 1024` 位元組）。手動編輯也受此限制。
- 重複編號、缺少欄位、型別錯誤、無效狀態、日期、時間戳記或 UTF-8 會顯示錯誤，欄位錯誤附上位置；未通過驗證不會寫入。

匯入入口拒絕空白日誌集合。內部儲存及匯出允許 `entries: []`，表示目前沒有日誌。

## 本機資料與語言

日誌獨立、以不可分割的寫入方式儲存至 Application Support 內的 `OshicueKit/diary.json`，重新啟動時讀取。若原檔案損壞，首次成功取代前會在相同目錄保留 `diary.recovery-<UUID>.json` 復原副本。此機制不取代使用者備份。

設定中的語言選擇統一套用至時間表、手帳、日誌及設定；日期顯示隨語言變化，內文、活動名稱及地址等使用者內容保持原樣。

## 日誌管理與系統外觀

- 0.4.0（build 10）從日誌頁右上角或設定→資料管理開啟「日誌管理」，頁面提供「紀錄管理」與「備份」。JSON 的匯入、預覽及匯出全部日誌功能保留在「備份」中。
- 依狀態、活動日期範圍及搜尋組合篩選，逐篇多選、全選目前結果或清除選取。變更篩選會清空選取；刪除前確認篇數及內文、摘要的刪除範圍，取消不刪除。確認僅移除所選日誌；其他日誌、手帳與時間表保留，刪除結果會儲存至本機。
- 日誌清單、編輯器、發布準備、管理、備份及設定均跟隨系統淺色／深色外觀，系統切換即時生效，已儲存內文與活動快照保留原內容。
