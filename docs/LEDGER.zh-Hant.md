# 手帳使用與資料格式

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

手帳以日曆記錄物販消費，管理團體、成員、所屬關係、代表色與預設價格，並統計數量與消費排名。資料儲存在本機，手帳備份與時間表、日誌備份分開。

## 開始使用

1. 在「成員與類型」新增團體及成員。同一成員兼任多個團體時，使用「關聯已有成員（兼任）」新增所屬關係，沿用同一個成員編號；同名但編號不同的成員不會自動合併。
2. 為各所屬關係分別設定代表色及預設單價。預設類型有拍立得、WIDE 拍立得、手機合照，也可新增類型；同一類型可設定不同幣別價格。成員名稱和頭像由各團體共用。
3. 點「＋」，選擇日期、成員所屬團體、類型、數量、幣別與實際單價。切換成員身分、類型或幣別會重新帶入相應預設價格；沒有預設價格時需填寫單價。數量須為正整數，單價可以為零。
4. 活動、城市、場地、地址與備註均可不填。可建立手帳活動，或從時間表選擇活動及場地，複製為手帳活動；之後修改時間表不會自動同步到手帳。
5. 日曆數字表示當日物販總數量，而非紀錄筆數。月份卡片顯示當月數量及各幣別消費；選定日期後可查看成員分團體彙總與逐筆紀錄。

數量代表類型的份數：照片按張計，新增票券類可按券計。

## 編輯、刪除與歷史快照

點日期下方的成員卡片：只有一筆消費時直接開啟編輯；有多筆時先選擇紀錄。也可展開逐筆紀錄進入編輯。表單帶入原有日期、身分、類型、數量、單價與選填資訊，儲存只更新該筆紀錄。編輯頁的「刪除這筆物販」需確認，刪除後數量與金額隨之扣除。

在「成員與類型」點成員編輯資料；團體標題旁的鉛筆開啟團體編輯。刪除成員或團體均需確認：

- 刪除成員：封存此成員及其在所有團體中的所屬關係。
- 刪除團體：封存團體及其所屬關係；兼任其他團體的成員仍可使用。

封存資料保留在備份中，既有消費、名稱、代表色、單價與統計均保留。新紀錄及改選身分只能使用有效所屬關係；歷史紀錄仍可保留原已刪除身分編輯，選擇器會標示「已刪除」。資料編輯頁沒有還原入口；匯入含同編號有效資料的備份可還原目錄資料，仍須通過完整合併驗證。

修改目錄名稱、代表色或預設價格不會改寫已儲存消費。編輯消費時，保留同一身分會保留成員、團體及顏色快照；保留同一類型會保留類型名稱快照。改選身分或類型時重新取得相應快照；實際單價及活動資訊依表單儲存。儲存前先驗證完整帳本，再以不可分割的方式寫入本機；失敗不會套用部分修改。

## 統計

統計支援日、月、年及生涯範圍，可依類型和團體篩選，依成員合計、成員分團體或團體排名。成員人數依篩選後不同的 `memberID` 計算。已封存團體仍可用於歷史統計篩選。

數量排名可合計所有幣別的份數，消費排名須選擇一種幣別；金額不會混加或自動換匯。彙總依類型列出數量與分幣別金額。排名採競賽名次，例如 `1、1、3`；同分依編號穩定排序，占比以目前篩選範圍的數量或單幣別消費為分母，總額為零時占比為零。排名顯示篩選範圍內最新紀錄的名稱與顏色快照；同日依紀錄編號排序取值。

## 範例帳本

首次沒有儲存檔案時載入虛構範例並立即儲存：2 個團體、3 位成員、4 個所屬關係、3 種類型、1 個活動、5 筆紀錄，總數量 16。範例日期依建立時的 `Asia/Shanghai` 日曆日及前兩日產生，當日數量 10；不會固定為範本中的日期。頁面不顯示範例標記。

既有帳本直接讀取原資料，修改或刪除範例後重新啟動不會還原。「載入手帳範例」只允許空帳本或未修改的範例帳本；空帳本須沒有團體、成員、所屬關係、活動與紀錄，類型為空或恰為預設三種。僅封存資料不會讓帳本變空。首次匯入可取代未修改的範例；任何已儲存範例編輯都會改採合併規則。

## JSON 欄位

[ledger-template.json](../Templates/ledger-template.json) 是獨立於時間表範本的可匯入範例。使用 UTF-8，`schemaVersion` 須為 `1`；以下六個陣列均必須存在，無資料時填 `[]`。各陣列內的 `id` 須唯一，編號和名稱不能只含空白。

| 陣列 | 必填欄位 | 選填欄位 |
| --- | --- | --- |
| `groups` | `id`、`name` | `isArchived` |
| `members` | `id`、`name` | `avatarJPEGBase64`、`isArchived`、`isFavorite` |
| `memberships` | `id`、`memberID`、`groupID`、`color`、`prices` | `isArchived` |
| `products` | `id`、`name` | 無 |
| `events` | `id`、`name` | `date`、`city`、`venue`、`address` |
| `records` | 見下表 | 見下表 |

`memberships` 引用同一檔案內的成員與團體，每對成員與團體只能有一個所屬關係。`color` 使用六位 RGB，例如 `#F28AAF`。`prices` 可為 `[]`；每項必填 `productID`、`currency`、`unitPriceMinor`，引用既有類型，同一所屬關係內各類型與幣別組合只能出現一次。

`isArchived` 為選填布林值，只有 `true` 表示封存；舊備份省略此欄位仍可匯入，版本號維持 `1`。有效所屬關係也要求成員與團體均未封存。封存資料仍須合法，手動整理備份時須保留歷史消費引用的成員、團體及所屬關係。

| `records` 欄位 | 要求與含義 |
| --- | --- |
| `id` | 必填，唯一消費編號；新增消費使用新編號，建議 UUID |
| `date` | 必填，有效西曆日期，嚴格使用 `yyyy-MM-dd`，例如 `2026-10-14` |
| `memberID`、`groupID`、`productID` | 必填，引用同一檔案的成員、團體、類型，且存在相應所屬關係 |
| `quantity` | 必填，正整數數量 |
| `unitPriceMinor` | 必填，非負整數單價，以幣別最小單位儲存 |
| `currency` | 必填，下表中的大寫幣別代碼 |
| `memberNameSnapshot`、`groupNameSnapshot`、`productNameSnapshot` | 必填，消費當時的名稱，不能只含空白 |
| `colorSnapshot` | 必填，消費當時的六位 RGB 代表色 |
| `eventID` | 選填，引用同一檔案內 `events` 的編號 |
| `eventNameSnapshot`、`citySnapshot`、`venueSnapshot`、`addressSnapshot`、`note` | 選填，消費當時的活動、城市、場地、地址與備註 |

消費日期以日曆日儲存，之後更換時區不會移動既有紀錄；活動日期可與消費日期不同。頭像欄位存放 JPEG 的 Base64 資料，而非檔案路徑。

## 金額精度與限制

總額為 `quantity × unitPriceMinor`，金額使用整數運算。介面填寫一般價格後轉換為最小單位；超過允許小數位的輸入會被拒絕，不會默默四捨五入。建議使用數字與小數點，不填貨幣符號或千位分隔符號；JSON 金額只能填整數。

| 幣別 | 小數位 | 介面價格範例 | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`、`KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`、`HKD`、`USD`、`THB`、`IDR`、`MYR` | 2 | `100.00` | `10000` |

以上為 App 目前實作的精度，`IDR` 與 `TWD` 同樣保留兩位最小單位。單筆乘積、數量合計及各幣別金額合計均檢查整數溢位。JSON 文字與編碼後帳本上限為 `20 × 1024 × 1024` 位元組（20 MiB）；每張匯入頭像解碼後上限為 `2 × 1024 × 1024` 位元組（2 MiB），並檢查 JPEG 結構。相簿原圖上限 10 MiB，儲存前縮至最長邊 512 像素並轉為 JPEG。

## 匯入、合併與備份

在手帳頂部開啟「手帳管理」，切換至「備份」，選擇一個或多個 JSON／文字檔，或貼上 JSON 驗證預覽後確認匯入。多檔先合併再預覽；空檔、無資料文件、無效欄位與衝突均會阻止匯入。檔案須自帶全部引用資料，不能依賴目前帳本補齊成員或團體。修改貼上的內容會使舊預覽失效。

未修改的範例帳本會被有效匯入取代；其他情況採合併規則：

- 團體、成員、所屬關係、類型與活動依 `id` 更新或新增；新檔未包含的舊資料保留。匯入可更新封存標記。
- 消費依 `id` 去除重複。完全相同的紀錄再次匯入不會重複計數；同編號內容不同會報錯，取消整次匯入。編輯消費請在 App 內操作，新消費使用新編號。
- 合併前後均驗證完整文件，包含所屬關係唯一性、引用關係、日期、快照、金額與大小；失敗保留原帳本。

匯出包含完整帳本、封存資料、歷史快照、價格與頭像。還原採合併方式，不會撤銷既有消費編輯；編輯後紀錄與舊備份同編號內容不同會產生衝突。請妥善保存匯出檔案，以便移轉或留存資料。

## 管理、最愛成員與系統外觀

- 0.4.0（build 10）的手帳頂部與設定→資料管理入口為「手帳管理」。頁面提供「紀錄管理」「資料清理」「備份」；原有 JSON 匯入、預覽及完整匯出仍在「備份」中。設定亦提供「日誌管理」。
- 物販紀錄可組合依日期範圍、成員、團體、類型、幣別、活動及搜尋篩選，再逐筆多選、全選目前結果或清除選取。變更任何篩選都會清空選取；沒有符合結果時不能刪除。確認前顯示所選紀錄筆數、總數量及各幣別金額；取消不刪除，明確確認後才移除所選紀錄並更新統計。
- 「刪除全部物販紀錄」不受目前篩選影響，須再次確認完整帳本的筆數、數量及各幣別金額。團體、成員、類型、活動目錄及日誌保留，可繼續新增紀錄。
- 「資料清理」支援搜尋、多選成員或團體。刪除成員會封存其所有團體身分；刪除團體僅封存本團體及所屬關係，兼任的其他身分保留。歷史物販、快照與統計保留，歷史紀錄仍可編輯；取消確認不會封存，還原目錄可匯入有效備份。
- 在「成員與類型」的成員編輯頁單獨設定或取消「最愛成員」。設定綁定成員編號，所有兼任身分共用；紀錄成員選擇頁頂部提供最愛專區，各團體身分仍有獨立顏色及價格，下方保留團體分組。新紀錄預設優先使用有效的最愛身分；關聯既有成員亦優先顯示最愛，已封存成員或身分不進入最愛快捷選擇。
- 成員的 `isFavorite` 是可選 Bool：僅 `true` 為最愛，`false`、省略或 `null` 均為未最愛。舊 JSON 仍可匯入，`schemaVersion` 維持 `1`；完整備份儲存最愛設定，依成員編號合併目錄時同步更新。
- App 跟隨系統淺色／深色外觀，涵蓋時間表、手帳、日誌、設定及所有編輯、選擇、管理和備份頁面；系統切換時介面同步變化，無須另外設定主題。成員代表色與歷史快照繼續保留。
