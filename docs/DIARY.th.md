# การใช้และสำรองบันทึกประจำวัน

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

บันทึกประจำวันใช้จดประสบการณ์จากการแสดง งานขายสินค้า และการเดินทางไปชมงาน ต้นฉบับอยู่ในอุปกรณ์และแก้ไขต่อได้ จากนั้นจึงคัดลอกหรือส่งออกเป็นข้อความสำหรับเผยแพร่ เมื่อใช้งานครั้งแรกจะไม่มีบันทึกที่ใส่มาให้ ตัวอย่างสมมติในแม่แบบต้องนำเข้าเอง

## สร้างและจัดระเบียบ

1. แตะปุ่มบวกในแท็บที่สาม “บันทึกประจำวัน” แล้วกรอกชื่อและเนื้อหาหลายบรรทัด Markdown ที่พิมพ์ไว้จะคงอยู่ แต่ตัวแก้ไขไม่มีหน้าตัวอย่างที่แสดงผล Markdown
2. กรอก “สรุปและประเด็นสำคัญ” การ์ดในรายการจะแสดงสรุปก่อน หากสรุปว่างจะแสดงต้นเนื้อหา และแสดงแท็กได้สูงสุดสามแท็ก
3. คั่นแท็กด้วยจุลภาค จุลภาคแบบจีน อัฒภาค หรือขึ้นบรรทัดใหม่ รองรับตัวคั่นทั้งแบบครึ่งความกว้างและเต็มความกว้าง ระบบจะตัดช่องว่างและ `#`／`＃` ที่หัวท้ายออก และตัดแท็กซ้ำโดยไม่แยกตัวพิมพ์ใหญ่เล็ก แต่ยังแยกเสียงไม่ก้องกับเสียงก้องในภาษาญี่ปุ่นและเครื่องหมายกำกับเสียงที่ต่างกัน
4. ใน “ข้อมูลงาน” เลือกงานที่มีอยู่ในสมุดบันทึกเพื่อนำชื่อ วันที่ตามปฏิทินเกรกอเรียน เมือง สถานที่ และที่อยู่มาใช้ หากไม่มีวันที่ที่ถูกต้องจะคงวันที่ที่เลือกอยู่ไว้ คุณกรอกเองหรือเพิ่มงานในสมุดบันทึกจากหน้าแก้ไขก็ได้
5. เลือก “ฉบับร่าง” หรือ “เรียบเรียงแล้ว” สถานะนี้ใช้จัดระเบียบและกรองข้อมูลในอุปกรณ์ ไม่ได้หมายถึงเผยแพร่แล้ว

ข้อมูลงานเป็นสำเนาสถานะที่เก็บไว้เฉพาะบันทึกนั้น การแก้ไขหรือลบงานในสมุดบันทึกจะไม่เปลี่ยนบันทึกที่บันทึกไว้ ต้องเลือกงานใหม่อีกครั้งจึงจะปรับสำเนานี้ การเปลี่ยนกลับไปกรอกเองจะยกเลิกเพียงการเชื่อมกับรหัสงาน ไม่ล้างข้อมูลที่นำมาแล้ว บันทึกประจำวันใช้งานแยกได้ โดยกรอกสถานที่และที่อยู่เองหรือนำมาจากสมุดบันทึก

รายการแบ่งกลุ่มตามวันที่ของงานจากใหม่ไปเก่า ภายในวันเดียวกันเรียงตามเวลาแก้ไขล่าสุด การค้นหาครอบคลุมชื่อ เนื้อหา สรุป แท็ก รวมถึงชื่องาน วันที่ เมือง สถานที่ และที่อยู่ คำค้นหลายคำที่คั่นด้วยช่องว่างต้องตรงทั้งหมด โดยอยู่คนละช่องข้อมูลก็ได้ กรองได้เป็นทั้งหมด ฉบับร่าง และเรียบเรียงแล้ว

## บันทึกอัตโนมัติและลบ

ระบบบันทึกอัตโนมัติหลังหยุดแก้ไขประมาณ 0.5 วินาที เมื่อแตะ “เสร็จสิ้น” หรือ “ปิด” เข้าเบื้องหลัง หรือออกจากหน้าแก้ไข จะพยายามบันทึกทันที หากล้มเหลวจะแสดงข้อผิดพลาดและปุ่มลองใหม่ “เสร็จสิ้น” และ “ปิด” จะออกจากหน้าเมื่อบันทึกสำเร็จเท่านั้น การเขียนที่ล้มเหลวจะไม่แทนที่ข้อมูลที่บันทึกแล้ว

การเปิดแบบฟอร์มเปล่าหรือเปลี่ยนเฉพาะวันที่หรือสถานะจะไม่สร้างบันทึกใหม่ ระบบเริ่มบันทึกเมื่อชื่อ เนื้อหา สรุป แท็ก ชื่องาน เมือง สถานที่ หรือที่อยู่มีเนื้อหาจริง บันทึกที่เคยบันทึกแล้วเก็บไว้ได้แม้ล้างข้อความ ทุกบันทึกต้องมีวันที่ของงานที่ถูกต้องเสมอ

ด้านล่างหน้าแก้ไขของบันทึกที่บันทึกแล้วมีปุ่มลบและต้องยืนยัน การลบเอาออกเฉพาะบันทึกประจำวันในอุปกรณ์ ไม่ลบงานในสมุดบันทึก รายการซื้อ หรือสำเนาที่ส่งออกแล้ว

## ส่งออกข้อความและสำรองข้อมูลทั้งหมด

“เตรียมเผยแพร่” จะบันทึกการแก้ไขปัจจุบันก่อนแสดงข้อความ คุณคัดลอก Markdown หรือข้อความธรรมดา ส่งออก `.md`／`.txt` หรือเปิดแผงแชร์ของ iOS ได้ ข้อความมีชื่อ ข้อมูลงาน แท็ก สรุป และเนื้อหา โดยคงการขึ้นบรรทัดใหม่ในเนื้อหาและสรุป การส่งออก Markdown จะใส่อักขระหลีกให้อักขระพิเศษแบบอินไลน์ในชื่อและข้อมูลงาน ส่วนเนื้อหาและสรุปคงต้นฉบับ คุณเลือกปลายทางแชร์และการดำเนินการถัดไปเอง แอปไม่เชื่อมบัญชีโซเชียลหรือเผยแพร่อัตโนมัติ

เปิด “จัดการบันทึกประจำวัน” แล้วเลือก “สำรองข้อมูล” จากมุมขวาบนของแท็บบันทึกประจำวัน หรือแท็บที่สี่ “การตั้งค่า” แล้ว “ส่งออกบันทึกทั้งหมด” เพื่อบันทึก JSON ฉบับเต็มผ่านหน้าจอไฟล์ของระบบ JSON เก็บรหัส สถานะ อาร์เรย์แท็ก สำเนาข้อมูลงาน เวลาสร้างและแก้ไข จึงเหมาะสำหรับนำเข้ากลับ ส่วน `.md`／`.txt` ใช้อ่านและแชร์ คุณต้องส่งออกและเก็บข้อมูลสำรองเอง ไม่ใช่การสำรองบนคลาวด์อัตโนมัติ และการแก้ไขต่อจะไม่อัปเดตไฟล์ที่ส่งออกไปแล้ว

## รูปแบบ JSON

[diary-template.json](../Templates/diary-template.json) เป็นตัวอย่างสมมติ ให้แทนที่ด้วยข้อมูลจริงและกำหนดรหัสใหม่ที่ไม่ซ้ำสำหรับบันทึกใหม่ ไฟล์ใช้ UTF-8 ช่องข้อมูลระดับบนสุดที่ต้องมีคือ `schemaVersion` (จำนวนเต็ม `1`) และ `entries` (อาร์เรย์)

| ช่องข้อมูล | ชนิด | ข้อกำหนด |
| --- | --- | --- |
| `id` | สตริง | ต้องมี ไม่ว่าง และไม่ซ้ำ แนะนำ UUID |
| `title` | สตริง | ต้องมี ฉบับร่างใช้ `""` ได้ |
| `body` | สตริง | ต้องมี เป็นเนื้อหาทั้งหมด เขียนการขึ้นบรรทัดใหม่ใน JSON เป็น `\n` ใช้ `""` ได้ |
| `summary` | สตริง | ต้องมี สรุปและประเด็นสำคัญ ใช้ `""` ได้ |
| `tags` | อาร์เรย์สตริง | ต้องมี หากไม่มีแท็กใช้ `[]` |
| `status` | สตริง | ต้องมี ใช้ได้เฉพาะ `draft` หรือ `ready` |
| `event` | ออบเจ็กต์ | ต้องมี ดูช่องข้อมูลในตารางถัดไป |
| `createdAt` | สตริง | ต้องมี เวลาสร้างแบบ ISO 8601 ที่ระบุเขตเวลา |
| `updatedAt` | สตริง | ต้องมี เวลาแก้ไข ต้องไม่ก่อน `createdAt` |

| ช่องข้อมูลใน `event` | ชนิด | ข้อกำหนด |
| --- | --- | --- |
| `ledgerEventID` | สตริงหรือ null | ไม่บังคับ ละไว้หรือใช้ `null` ได้ หากเป็นสตริงต้องไม่ว่าง งานไม่จำเป็นต้องยังอยู่ในสมุดบันทึก |
| `name` | สตริง | ต้องมี ชื่องาน ใช้ `""` ได้ |
| `date` | สตริง | ต้องมี วันที่เกรกอเรียนที่ถูกต้องในรูปแบบ `yyyy-MM-dd` อย่างเคร่งครัด เช่น `2026-10-14` |
| `city` | สตริง | ต้องมี เมือง ใช้ `""` ได้ |
| `venue` | สตริง | ต้องมี สถานที่ ใช้ `""` ได้ |
| `address` | สตริง | ต้องมี ที่อยู่เต็ม ใช้ `""` ได้ |

`event.date` เป็นปีเดือนวัน ไม่มีเขตเวลาหรือชั่วโมงนาทีวินาที เวลาสร้างและแก้ไขเป็นเวลาสัมบูรณ์ ส่งออกด้วยความละเอียดมิลลิวินาที เช่น `2026-01-01T00:00:00.000Z` การนำเข้ารองรับออฟเซ็ต UTC ที่ชัดเจนด้วย เช่น `2026-01-01T09:00:00.000+09:00` ห้ามละ `Z` หรือออฟเซ็ต วันที่งานอาจอยู่ก่อนเวลาเขียนบันทึกย้อนหลัง ข้อมูลสำรองบันทึกประจำวันไม่ต้องอาศัยข้อมูลสำรองสมาชิก กลุ่ม หรือสมุดบันทึก

## นำเข้าและข้อขัดแย้ง

ใน “จัดการบันทึกประจำวัน” → “สำรองข้อมูล” เลือกไฟล์ UTF-8 JSON หนึ่งไฟล์หรือหลายไฟล์ หรือวาง JSON แล้วตรวจสอบและดูตัวอย่าง ตัวอย่างแสดงจำนวนบันทึกใหม่และที่มีอยู่แล้ว และจะเขียนข้อมูลหลังยืนยันเท่านั้น

- บันทึกที่มีรหัสเดียวกันและเนื้อหาเหมือนกันทั้งหมดจะตัดซ้ำ โดยเปรียบเทียบเวลาสร้างและแก้ไขที่ความละเอียดมิลลิวินาที
- หากรหัสเดียวกันแต่เนื้อหาต่างกัน เช่น เนื้อหา สรุป แท็ก สถานะ ข้อมูลงาน หรือเวลา การนำเข้าทั้งชุดจะหยุดและเก็บข้อมูลเดิมไว้ หากต้องการแก้บันทึกเดิมให้แก้ในแอป หากต้องการเก็บอีกฉบับให้ใช้รหัสใหม่
- การนำเข้าเพิ่มเฉพาะบันทึกใหม่ บันทึกเดิมที่ไม่มีในไฟล์ยังอยู่ กฎข้อขัดแย้งเดียวกันใช้ระหว่างไฟล์หลายไฟล์ที่เลือกด้วย
- แต่ละข้อมูลนำเข้าและข้อมูลหลังรวมมีขนาดสูงสุด 20 MiB (`20 * 1024 * 1024` ไบต์) การแก้ไขเองอยู่ภายใต้ขีดจำกัดนี้ด้วย
- รหัสซ้ำ ช่องข้อมูลขาดหาย ชนิดผิด สถานะ วันที่ เวลา หรือ UTF-8 ไม่ถูกต้องจะแสดงข้อผิดพลาด ข้อผิดพลาดของช่องข้อมูลจะแนบตำแหน่ง หากตรวจสอบไม่ผ่านจะไม่เขียนข้อมูล

หน้านำเข้าปฏิเสธชุดบันทึกว่าง การเก็บภายในและการส่งออกอนุญาต `entries: []` ซึ่งหมายถึงขณะนี้ไม่มีบันทึก

## ข้อมูลในอุปกรณ์และภาษา

บันทึกประจำวันเก็บแยกและเขียนแบบอะตอมมิกใน `OshicueKit/diary.json` ภายใต้ Application Support และอ่านเมื่อเริ่มใหม่ หากไฟล์ต้นฉบับเสียหาย ระบบเก็บสำเนากู้คืน `diary.recovery-<UUID>.json` ในโฟลเดอร์เดียวกันก่อนแทนที่สำเร็จครั้งแรก กลไกนี้ไม่แทนการสำรองข้อมูลของผู้ใช้

การเลือกภาษาในตั้งค่าใช้ร่วมกันกับตารางเวลา สมุดบันทึก บันทึกประจำวัน และการตั้งค่า รูปแบบวันที่เปลี่ยนตามภาษา แต่เนื้อหา ชื่องาน ที่อยู่ และข้อมูลที่ผู้ใช้กรอกยังคงเดิม

## การจัดการบันทึกประจำวันและรูปลักษณ์ตามระบบ

- ใน 0.4.0 (build 10) เปิด “จัดการบันทึกประจำวัน” จากมุมขวาบนของบันทึกหรือการตั้งค่า→จัดการข้อมูล มี “จัดการรายการ” และ “สำรองข้อมูล” การนำเข้า JSON ดูตัวอย่างและส่งออกทุกบันทึกยังอยู่ใน “สำรองข้อมูล”
- รวมตัวกรองสถานะ ช่วงวันที่งานและคำค้น แล้วเลือกหลายบันทึกทีละฉบับ เลือกผลลัพธ์ปัจจุบันทั้งหมดหรือล้างการเลือก เปลี่ยนตัวกรองจะล้างการเลือก ก่อนลบยืนยันจำนวนบันทึกและการลบเนื้อหากับสรุป การยกเลิกไม่ลบ ยืนยันแล้วลบเฉพาะที่เลือก บันทึกอื่น สมุดบันทึกและตารางยังอยู่ และบันทึกผลลบไว้ในเครื่อง
- รายการบันทึก ตัวแก้ไข เตรียมเผยแพร่ จัดการ สำรองและการตั้งค่าเปลี่ยนโหมดสว่างหรือมืดตามระบบทันที เนื้อหาที่บันทึกและสำเนาข้อมูลงานยังเหมือนเดิม
