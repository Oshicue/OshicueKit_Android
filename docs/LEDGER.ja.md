# 手帳の使い方とデータ形式

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

手帳では物販の購入をカレンダーに記録し、グループ、メンバー、所属関係、担当カラー、既定価格を管理できます。数量と支出のランキングにも対応しています。データは端末に保存され、手帳のバックアップは時間割・日記のバックアップと別です。

## 使い始める

1. 「メンバー・種類」でグループとメンバーを追加します。複数グループを兼任するメンバーは「既存のメンバーと連携」で所属関係を追加し、同じメンバー ID を使います。同名でも ID が異なるメンバーは自動統合されません。
2. 所属関係ごとに担当カラーと既定の単価を設定します。初期の種類はチェキ、WIDE チェキ、スマホ撮影です。種類を追加したり、同じ種類に複数通貨の価格を設定したりできます。メンバー名とアイコンは各グループで共通です。
3. 「＋」を押し、日付、メンバーの所属グループ、種類、数量、通貨、実際の単価を選びます。所属関係・種類・通貨を変更すると、対応する既定価格が再入力されます。既定価格がなければ単価を入力してください。数量は正の整数、単価はゼロでも構いません。
4. イベント、市区町村、会場、住所、メモは任意です。手帳のイベントを作成するか、時間割からイベントと会場を選んで手帳のイベントとしてコピーできます。その後の時間割の変更は手帳に自動反映されません。
5. カレンダーの数字はその日の物販の総数量で、記録件数ではありません。月のカードには月間数量と通貨別支出が表示されます。日付を選ぶとメンバーのグループ別集計と個別記録を確認できます。

数量は種類ごとの個数です。写真は枚数、券の種類を追加した場合は券数として数えられます。

## 編集・削除と履歴のスナップショット

日付の下のメンバーカードを押すと、購入が 1 件なら直接編集画面が開き、複数なら先に記録を選びます。個別記録の一覧を展開して編集することもできます。フォームには元の日付、所属関係、種類、数量、単価、任意情報が入ります。保存で更新されるのは選択した記録だけです。「この物販を削除」は確認後に実行され、数量と金額が差し引かれます。

「メンバー・種類」でメンバーを押すと情報を編集できます。グループ見出し横の鉛筆からグループを編集できます。どちらの削除にも確認が必要です。

- メンバーの削除：メンバーと全グループの所属関係をアーカイブします。
- グループの削除：グループとその所属関係をアーカイブします。他のグループを兼任するメンバーは、そのグループで引き続き使用できます。

アーカイブ済みデータはバックアップに残り、既存の購入、名称、カラー、単価、統計も保持されます。新規記録や所属関係の変更先には有効な所属関係のみ使えます。過去の記録は元の削除済み所属関係のまま編集でき、選択肢に削除済みと表示されます。カタログの編集画面に復元ボタンはありません。同じ ID の有効なカタログ項目を含むバックアップを読み込むと復元できますが、完全なマージ検証を通過する必要があります。

カタログの名称、カラー、既定価格を変更しても保存済み購入は書き換わりません。購入の編集で所属関係を維持するとメンバー名・グループ名・カラーのスナップショットが保持され、種類を維持すると種類名のスナップショットが保持されます。所属関係や種類を変えると対応する新しいスナップショットを取得します。実際の単価とイベント情報はフォームの内容を保存します。帳簿全体の検証後に端末へ一括保存し、失敗時に変更の一部だけを反映することはありません。

## 統計

日・月・年・通算の期間、種類とグループの絞り込み、メンバー合算・メンバーのグループ別・グループ単位のランキングに対応しています。メンバー人数は絞り込み後の異なる `memberID` の数です。アーカイブ済みグループも履歴の絞り込みに使えます。

数量ランキングでは全通貨の個数を合計できますが、支出ランキングには通貨を 1 つ選ぶ必要があります。異なる通貨の金額は合算せず、自動換算も行いません。集計には種類別数量と通貨別金額を表示します。同順位は `1、1、3` のような競技順位で、同点の表示順は ID によって安定します。割合の分母は現在の絞り込み範囲の数量または単一通貨の支出総額です。総額ゼロなら割合もゼロです。ランキングの名称とカラーは絞り込み範囲で最新の記録のスナップショットを使い、同日の記録は ID 順で選びます。

## サンプル帳簿

初回起動で保存ファイルがない場合、架空のサンプルを読み込んですぐに保存します。内訳は 2 グループ、3 メンバー、4 所属関係、3 種類、1 イベント、5 記録で、総数量は 16 です。日付は作成時の `Asia/Shanghai` の暦日とその前 2 日で生成され、作成日の数量は 10 です。テンプレートの固定日付は使いません。サンプルを示すバッジは表示されません。

既存の帳簿は保存データを読み込みます。サンプルを編集・削除しても再起動で復活しません。サンプルの読み込みは空の帳簿か未編集のサンプル帳簿に限ります。空とはグループ・メンバー・所属関係・イベント・記録がなく、種類が空または初期の 3 種類と完全に一致する状態です。アーカイブだけでは空になりません。初回読み込みは未編集のサンプルを置き換えられますが、サンプルへの編集を保存した後はマージになります。

## JSON フィールド

[ledger-template.json](../Templates/ledger-template.json) は時間割テンプレートとは別の読み込み可能なサンプルです。UTF-8 を使い、`schemaVersion` は `1` にします。次の 6 配列はすべて必要で、データがなければ `[]` にします。各配列内の `id` は一意とし、ID と名称は空白のみにはできません。

| 配列 | 必須フィールド | 任意フィールド |
| --- | --- | --- |
| `groups` | `id`、`name` | `isArchived` |
| `members` | `id`、`name` | `avatarJPEGBase64`、`isArchived`、`isFavorite` |
| `memberships` | `id`、`memberID`、`groupID`、`color`、`prices` | `isArchived` |
| `products` | `id`、`name` | なし |
| `events` | `id`、`name` | `date`、`city`、`venue`、`address` |
| `records` | 下表参照 | 下表参照 |

`memberships` は同じファイルのメンバーとグループを参照し、各メンバーとグループの組み合わせに所属関係は 1 つだけです。`color` は `#F28AAF` のような 6 桁の RGB です。`prices` は `[]` でも構いません。各価格には `productID`、`currency`、`unitPriceMinor` が必要で、既存の種類を参照します。同一所属関係内で種類と通貨の組み合わせは重複できません。

`isArchived` は任意の真偽値で、`true` の場合のみアーカイブ済みです。このフィールドがない古いバックアップも読み込め、バージョンは `1` のままです。有効な所属関係ではメンバーとグループもアーカイブされていない必要があります。アーカイブ済み項目も有効なデータでなければなりません。バックアップを手作業で整理する際は、過去の購入が参照するメンバー、グループ、所属関係を残してください。

| `records` フィールド | 要件と意味 |
| --- | --- |
| `id` | 必須。一意の購入 ID。新しい購入には新しい ID を使い、UUID を推奨 |
| `date` | 必須。有効なグレゴリオ暦の日付。厳密な `yyyy-MM-dd` 形式。例：`2026-10-14` |
| `memberID`、`groupID`、`productID` | 必須。同じファイルのメンバー・グループ・種類を参照し、対応する所属関係が存在すること |
| `quantity` | 必須。正の整数の数量 |
| `unitPriceMinor` | 必須。通貨の最小単位で表す非負整数の単価 |
| `currency` | 必須。下表の大文字通貨コード |
| `memberNameSnapshot`、`groupNameSnapshot`、`productNameSnapshot` | 必須。購入時の名称。空白のみは不可 |
| `colorSnapshot` | 必須。購入時の 6 桁 RGB 担当カラー |
| `eventID` | 任意。同じファイルの `events` の ID を参照 |
| `eventNameSnapshot`、`citySnapshot`、`venueSnapshot`、`addressSnapshot`、`note` | 任意。購入時のイベント、市区町村、会場、住所、メモ |

購入日は暦日として保存され、後からタイムゾーンを変えても移動しません。イベント日と購入日は異なっていても構いません。アイコンのフィールドにはファイルパスではなく Base64 エンコードした JPEG データを入れます。

## 金額の精度と制限

総額は `quantity × unitPriceMinor` で、整数演算を使います。画面では通常の価格を入力し、最小単位に変換して保存します。許容桁数を超える小数は拒否し、暗黙の丸めはしません。数字と小数点を使い、通貨記号や桁区切りは付けないでください。JSON の金額は整数のみです。

| 通貨 | 小数桁数 | 画面の価格例 | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`、`KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`、`HKD`、`USD`、`THB`、`IDR`、`MYR` | 2 | `100.00` | `10000` |

これは現在のアプリ実装の精度です。`IDR` と `TWD` も小数 2 桁の最小単位を保持します。各購入の積、数量合計、通貨ごとの金額合計で整数オーバーフローを確認します。JSON テキストとエンコード後の帳簿の上限は `20 × 1024 × 1024` バイト（20 MiB）です。読み込むアイコンはデコード後 `2 × 1024 × 1024` バイト（2 MiB）までで、JPEG 構造も検証します。写真ライブラリの元画像は 10 MiB までとし、保存前に長辺を最大 512 ピクセルへ縮小して JPEG に変換します。

## 読み込み・マージ・バックアップ

手帳上部の「手帳の管理」を開いて「バックアップ」を選び、JSON／テキストファイルを 1 つ以上選ぶか、JSON を貼り付けてプレビューを検証してから読み込みを確定します。複数ファイルはマージ後にプレビューします。空ファイル、データのない文書、不正フィールド、競合は読み込みを阻止します。ファイルには参照される全項目が必要で、現在の帳簿から不足するメンバーやグループを補うことはできません。貼り付けた内容を変更すると前のプレビューは無効になります。

有効な読み込みは未編集のサンプル帳簿を置き換えます。それ以外は次のマージ規則を使います。

- グループ、メンバー、所属関係、種類、イベントは `id` ごとに更新・追加します。新しいファイルにない既存項目は残ります。アーカイブの状態も更新できます。
- 購入は `id` で重複を除きます。同一内容の再読み込みは二重計上されません。同じ ID で内容が異なる記録はエラーとなり、読み込み全体を取り消します。購入はアプリ内で編集し、新しい購入には新しい ID を使ってください。
- マージ前後に所属関係の一意性、参照、日付、スナップショット、金額、サイズを含めて文書全体を検証します。失敗時は元の帳簿を保持します。

書き出しには帳簿全体、アーカイブ済み項目、過去のスナップショット、価格、アイコンが含まれます。復元はマージであり、既存購入の編集を取り消しません。編集済み記録と同じ ID で内容の異なる古いバックアップは競合します。移行や記録保管のため、書き出したファイルを保存してください。

## 管理、お気に入りメンバー、システムの外観

- 0.4.0（build 10）では、手帳上部と設定→データ管理から「手帳の管理」を開きます。「記録の管理」「資料の整理」「バックアップ」があり、既存の JSON 読み込み、プレビュー、全体の書き出しは「バックアップ」に残ります。設定には「日記の管理」もあります。
- 購入記録を日付範囲、メンバー、グループ、種類、通貨、イベント、検索で絞り込み、個別に複数選択、現在の結果をすべて選択、または選択解除できます。条件を変更すると選択は解除され、該当結果がなければ削除できません。確認には選択件数、総数量、通貨別金額が表示されます。キャンセルでは削除せず、明示的な確認後に選択した記録だけを削除し、統計を更新します。
- 「すべての物販記録を削除」は現在の条件に関係なく帳簿全体に適用され、全件数、数量、通貨別金額を再確認します。グループ、メンバー、種類、イベントの資料と日記は残り、記録を追加できます。
- 「資料の整理」ではメンバーやグループの検索と複数選択ができます。メンバー削除はすべての所属をアーカイブし、グループ削除はそのグループと所属だけをアーカイブします。他グループの兼任所属は残ります。過去の購入、スナップショット、統計は保持され、過去の記録も編集できます。キャンセルではアーカイブせず、有効なバックアップの読み込みで資料を復元できます。
- 「メンバーと種類」のメンバー編集で「お気に入りメンバー」を個別に設定・解除します。設定はメンバー ID に属し、兼任する全所属で共有されます。購入のメンバー選択では上部にお気に入りを表示し、各所属は独立した色と価格を保持します。通常のグループ別一覧も下に残ります。新規記録は有効なお気に入り所属を優先し、既存メンバーの関連付けでもお気に入りを先に表示します。アーカイブ済みメンバーや所属はショートカットに出ません。
- メンバーの `isFavorite` は任意の Bool で、`true` のみがお気に入りです。`false`、省略、`null` は未設定として扱います。古い JSON も読み込め、`schemaVersion` は `1` のままです。完全バックアップに設定を保存し、メンバー ID による資料のマージで更新します。
- アプリはタイムテーブル、手帳、日記、設定とすべての編集、選択、管理、バックアップ画面でシステムのライト／ダーク外観に従います。別のテーマ設定は不要で、システムの変更が画面に反映されます。メンバーの色と過去のスナップショットは保持します。
