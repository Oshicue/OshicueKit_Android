# 日誌使用同備份

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

日誌用嚟記錄演出、物販同遠征經歷。原稿儲存喺本機，可以繼續編輯，再複製或匯出成發布用嘅文字。首次使用冇預設日誌；範本入面嘅虛構例子要自行匯入。

## 新增同整理

1. 喺第三個「日誌」頁撳加號，填寫標題同多行正文。正文會保留你輸入嘅 Markdown，編輯器冇 Markdown 渲染預覽。
2. 填寫「摘要同重點」。列表卡片會先顯示摘要，摘要留空就顯示正文開頭，最多顯示三個標籤。
3. 標籤用逗號、頓號、分號或換行分隔，支援半形同全形分隔符號。會自動移除頭尾空白同 `#`／`＃`，忽略大小寫去除重複；日文清濁音同唔同重音仍然係唔同標籤。
4. 喺「活動資料」揀現有手帳活動，帶入名稱、公曆日期、城市、場館同地址；如果冇有效日期，就保留而家揀咗嘅日期。亦可以手動填寫，或者喺編輯頁新增手帳活動。
5. 揀「草稿」或者「已整理」；狀態只用嚟本機整理同篩選，唔代表已經發布。

活動資料係日誌自己嘅快照。修改或刪除手帳活動唔會改寫已儲存日誌；再揀入活動先會更新快照。轉返手動填寫只會解除活動編號關聯，唔會清空已帶入資料。日誌可以獨立使用，場館同地址由用戶填寫或者由手帳帶入。

列表按活動日期由近到遠分組，同一日就按最近修改時間排序。搜尋涵蓋標題、正文、摘要、標籤，同活動名稱、日期、城市、場館、地址；用空白分隔嘅多個詞要全部符合，可以分別出現喺唔同欄位。可以篩選全部、草稿、已整理。

## 自動儲存同刪除

停止修改大約 0.5 秒之後會自動儲存。撳「完成」「關閉」、進入背景或者離開編輯頁，會即刻嘗試儲存。儲存失敗會顯示錯誤同重試入口；「完成」「關閉」要儲存成功先退出，寫入失敗唔會取代已儲存資料。

只開空白表格、只改日期或者狀態，唔會建立新日誌；標題、正文、摘要、標籤，或者活動名稱、城市、場館、地址有實際內容先會開始儲存。已儲存日誌清空文字後仍然可以保留。每篇日誌都要有有效活動日期。

已儲存日誌嘅編輯頁底部有「刪除日誌」，要確認先執行。刪除只會移除本機日誌，唔會刪除手帳活動、消費記錄或者已匯出嘅副本。

## 文字匯出同完整備份

「準備發布」會先儲存而家嘅修改，再顯示文字。可以複製 Markdown 或純文字、匯出 `.md`／`.txt`，或者開啟 iOS 系統分享面板。文字包括標題、活動資料、標籤、摘要同正文；正文、摘要會保留原本換行。Markdown 匯出會將標題同活動資料嘅行內特殊字元加上逸出處理，正文同摘要保留原文。分享對象同之後嘅操作由用戶選擇，App 唔會連接社交帳戶或者自動發布。

喺日誌頁右上角或者第四個「設定」頁開啟「日誌管理」，轉去「備份」，「匯出全部日誌」會透過系統檔案面板儲存完整 JSON。JSON 保留編號、狀態、標籤陣列、活動快照，同建立、修改時間，適合再次匯入；`.md`／`.txt` 用嚟閱讀同分享。備份要自行匯出同保管，唔係自動雲端備份；繼續編輯唔會更新已匯出檔案。

## JSON 格式

[diary-template.json](../Templates/diary-template.json) 係虛構例子。請改成實際記錄，新增日誌要用新嘅唯一編號；檔案採用 UTF-8。最外層必填 `schemaVersion`（整數 `1`）同 `entries`（陣列）。

| 欄位 | 類型 | 要求 |
| --- | --- | --- |
| `id` | 字串 | 必填、非空而且唯一，建議用 UUID。 |
| `title` | 字串 | 必填，草稿可以係 `""`。 |
| `body` | 字串 | 必填，完整正文；JSON 換行寫成 `\n`，可以係 `""`。 |
| `summary` | 字串 | 必填，摘要同重點，可以係 `""`。 |
| `tags` | 字串陣列 | 必填，冇標籤就寫 `[]`。 |
| `status` | 字串 | 必填，只可以係 `draft` 或 `ready`。 |
| `event` | 物件 | 必填，欄位見下表。 |
| `createdAt` | 字串 | 必填，有時區嘅 ISO 8601 建立時間。 |
| `updatedAt` | 字串 | 必填，修改時間，唔可以早過 `createdAt`。 |

| `event` 欄位 | 類型 | 要求 |
| --- | --- | --- |
| `ledgerEventID` | 字串或 null | 選填，可以唔寫或者係 `null`；字串唔可以空白，唔要求活動仍然喺手帳入面。 |
| `name` | 字串 | 必填，活動名稱，可以係 `""`。 |
| `date` | 字串 | 必填，有效公曆日期，要嚴格用 `yyyy-MM-dd`，例如 `2026-10-14`。 |
| `city` | 字串 | 必填，城市，可以係 `""`。 |
| `venue` | 字串 | 必填，場館，可以係 `""`。 |
| `address` | 字串 | 必填，完整地址，可以係 `""`。 |

`event.date` 係年月日，冇時區或者時分秒。建立同修改時間係絕對時間，匯出用毫秒精度，例如 `2026-01-01T00:00:00.000Z`。匯入亦接受明確 UTC 偏移，例如 `2026-01-01T09:00:00.000+09:00`；唔可以漏咗 `Z` 或偏移。活動日期可以早過之後補寫日誌嘅建立時間。日誌備份唔需要成員、團體或者手帳備份。

## 匯入同衝突

喺「日誌管理」嘅「備份」揀一個或多個 UTF-8 JSON 檔案，或者貼上 JSON 再撳「檢查並預覽」。預覽會列出新增同已存在數量，確認先寫入。

- 相同編號而且全部內容相同嘅日誌會去除重複；建立、修改時間按毫秒精度比較。
- 相同編號但內容唔同，包括正文、摘要、標籤、狀態、活動資料或者時間戳唔同，整次匯入都會停止，保留原資料。修改舊日誌請喺 App 入面編輯；想保留另一版本就用新編號。
- 匯入只會增加新日誌，原資料中冇喺檔案出現嘅日誌會保留。多個所選檔案之間都會用相同衝突規則。
- 每份輸入同合併後資料上限係 20 MiB（`20 * 1024 * 1024` 位元組）。手動編輯都有同樣限制。
- 重複編號、缺少欄位、類型錯誤、無效狀態、日期、時間戳或者 UTF-8 都會提示錯誤，欄位錯誤會附上位置；未通過驗證唔會寫入。

匯入入口會拒絕空日誌集合。內部儲存同匯出容許 `entries: []`，代表而家冇日誌。

## 本機資料同語言

日誌獨立、以原子方式儲存喺 Application Support 入面嘅 `OshicueKit/diary.json`，重開時讀取。如果原檔案損壞，首次成功取代之前會喺同一目錄保留 `diary.recovery-<UUID>.json` 復原副本。呢個機制唔可以取代用戶備份。

設定入面嘅語言選擇會統一套用到時間表、手帳、日誌同設定；日期顯示會跟語言變，正文、活動名稱同地址等用戶內容會保留原樣。

## 日誌管理同系統外觀

- 0.4.0（build 10）喺日誌頁右上角或者設定→資料管理開啟「日誌管理」，頁面有「記錄管理」同「備份」。JSON 匯入、預覽同匯出全部日誌功能保留喺「備份」內。
- 按狀態、活動日期範圍同搜尋組合篩選，逐篇多選、全選目前結果或者清除選取。改篩選會清空選取；刪除前確認篇數同正文、摘要嘅刪除範圍，取消唔會刪除。確認只移除所選日誌；其他日誌、手帳同時間表保留，刪除結果會存喺本機。
- 日誌列表、編輯器、發布準備、管理、備份同設定都跟系統淺色／深色外觀，系統切換即時生效，已存正文同活動快照保持原內容。
