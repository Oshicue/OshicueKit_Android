# 수첩 사용법과 데이터 형식

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

수첩은 달력에 물판 구매를 기록하고 그룹, 멤버, 소속 관계, 대표 색상, 기본 가격을 관리하며 수량과 지출 순위를 보여 줍니다. 데이터는 기기에 저장됩니다. 수첩 백업은 시간표 및 일기 백업과 별개입니다.

## 시작하기

1. 「멤버 및 유형」에서 그룹과 멤버를 추가합니다. 여러 그룹을 겸하는 멤버는 「기존 멤버 연결」로 소속 관계를 추가하여 같은 멤버 ID를 사용하세요. 이름이 같아도 ID가 다르면 자동으로 합쳐지지 않습니다.
2. 소속 관계마다 대표 색상과 기본 단가를 설정합니다. 기본 유형은 체키, WIDE 체키, 휴대폰 사진이며 다른 유형을 추가할 수 있습니다. 같은 유형에 여러 통화의 가격을 설정할 수도 있습니다. 멤버 이름과 프로필 사진은 그룹 간에 공유됩니다.
3. 「＋」를 누르고 날짜, 멤버의 그룹, 유형, 수량, 통화, 실제 단가를 선택합니다. 소속 관계·유형·통화를 바꾸면 해당 기본 가격이 다시 입력됩니다. 기본 가격이 없으면 단가를 입력해야 합니다. 수량은 양의 정수여야 하며 단가는 0이어도 됩니다.
4. 행사, 도시, 공연장, 주소, 메모는 선택 사항입니다. 수첩 행사를 만들거나 시간표의 행사와 공연장을 골라 수첩 행사로 복사할 수 있습니다. 이후 시간표 변경은 수첩에 자동 반영되지 않습니다.
5. 달력 숫자는 해당 날짜의 구매 총수량이며 기록 건수가 아닙니다. 월별 카드에는 월간 수량과 통화별 지출이 표시됩니다. 날짜를 고르면 멤버의 그룹별 요약과 개별 기록을 볼 수 있습니다.

수량은 선택한 유형의 개수입니다. 사진은 장수, 추가한 티켓 유형은 티켓 수로 셀 수 있습니다.

## 수정·삭제와 과거 스냅샷

날짜 아래 멤버 카드를 누르면 구매가 한 건일 때 바로 수정 화면이 열리고, 여러 건이면 먼저 기록을 선택합니다. 개별 기록 목록을 펼쳐 수정할 수도 있습니다. 기존 날짜, 소속, 유형, 수량, 단가, 선택 정보가 입력되며 저장은 선택한 기록만 갱신합니다. 수정 화면의 구매 삭제는 확인이 필요하며 삭제하면 수량과 금액이 차감됩니다.

「멤버 및 유형」에서 멤버를 눌러 정보를 수정하고, 그룹 제목 옆 연필을 눌러 그룹을 수정합니다. 멤버와 그룹 삭제 모두 확인이 필요합니다.

- 멤버 삭제: 멤버와 모든 그룹의 소속 관계를 보관 처리합니다.
- 그룹 삭제: 그룹과 해당 그룹의 소속 관계를 보관 처리합니다. 다른 그룹을 겸하는 멤버는 그 그룹에서 계속 사용할 수 있습니다.

보관된 데이터는 백업에 남고 기존 구매, 이름, 색상, 단가, 통계도 유지됩니다. 새 기록이나 소속 변경에는 활성 소속 관계만 사용할 수 있습니다. 과거 기록은 원래 삭제된 소속을 유지한 채 수정할 수 있으며 선택 목록에 삭제됨으로 표시됩니다. 자료 수정 화면에는 복원 기능이 없습니다. 같은 ID의 활성 자료가 담긴 백업을 가져오면 자료를 복원할 수 있으나 전체 병합 검증을 통과해야 합니다.

자료의 이름, 색상, 기본 가격을 바꿔도 저장된 구매는 바뀌지 않습니다. 구매 수정 시 같은 소속을 유지하면 멤버·그룹 이름과 색상 스냅샷이 유지되고, 같은 유형을 유지하면 유형 이름 스냅샷이 유지됩니다. 소속이나 유형을 바꾸면 해당 스냅샷을 새로 가져옵니다. 실제 단가와 행사 정보는 입력 양식대로 저장됩니다. 전체 수첩을 검증한 뒤 기기에 한 번에 저장하며, 실패하면 일부 변경만 반영하지 않습니다.

## 통계

일·월·연·전체 기간, 유형 및 그룹 필터, 멤버 합산·멤버의 그룹별·그룹별 순위를 지원합니다. 멤버 수는 필터링된 기록의 서로 다른 `memberID` 개수입니다. 보관된 그룹도 과거 통계 필터에 사용할 수 있습니다.

수량 순위는 모든 통화의 개수를 합산할 수 있지만 지출 순위는 통화 하나를 선택해야 합니다. 서로 다른 통화 금액을 합치거나 자동 환전하지 않습니다. 요약은 유형별 수량과 통화별 금액을 보여 줍니다. 공동 순위는 `1、1、3`처럼 계산하며 동점은 ID로 일관되게 정렬합니다. 비율의 분모는 현재 필터 범위의 수량 또는 단일 통화 지출 총액이며 총액이 0이면 비율도 0입니다. 순위 이름과 색상은 필터 범위 내 가장 최근 기록의 스냅샷을 사용하며 같은 날짜는 기록 ID 순으로 선택합니다.

## 예시 수첩

첫 실행에 저장 파일이 없으면 가상 예시를 불러와 즉시 저장합니다. 그룹 2개, 멤버 3명, 소속 관계 4개, 유형 3개, 행사 1개, 기록 5건으로 총수량은 16입니다. 날짜는 생성 시점의 `Asia/Shanghai` 달력 날짜와 그 전 이틀을 사용하며 생성 당일 수량은 10입니다. 템플릿 날짜로 고정되지 않습니다. 예시 표시 배지는 없습니다.

기존 수첩은 저장된 자료를 읽으며 수정하거나 삭제한 예시는 재실행해도 복구되지 않습니다. 예시 불러오기는 빈 수첩이나 수정하지 않은 예시 수첩에서만 가능합니다. 빈 수첩은 그룹·멤버·소속·행사·기록이 없고 유형도 없거나 기본 세 유형과 정확히 일치해야 합니다. 자료를 보관 처리하는 것만으로 비워지지는 않습니다. 최초 가져오기는 수정하지 않은 예시를 대체할 수 있지만 예시 수정을 저장하면 이후에는 병합 규칙을 사용합니다.

## JSON 필드

[ledger-template.json](../Templates/ledger-template.json)은 시간표 템플릿과 별개인 가져오기 예시입니다. UTF-8을 사용하고 `schemaVersion`은 `1`이어야 합니다. 아래 배열 여섯 개는 모두 필수이며 비어 있으면 `[]`로 작성합니다. 각 배열 안의 `id`는 고유해야 하며 ID와 이름은 공백만으로 작성할 수 없습니다.

| 배열 | 필수 필드 | 선택 필드 |
| --- | --- | --- |
| `groups` | `id`, `name` | `isArchived` |
| `members` | `id`, `name` | `avatarJPEGBase64`, `isArchived`、`isFavorite` |
| `memberships` | `id`, `memberID`, `groupID`, `color`, `prices` | `isArchived` |
| `products` | `id`, `name` | 없음 |
| `events` | `id`, `name` | `date`, `city`, `venue`, `address` |
| `records` | 아래 표 참조 | 아래 표 참조 |

`memberships`는 같은 파일에 정의한 멤버와 그룹을 참조합니다. 멤버와 그룹의 조합마다 소속 관계는 하나만 허용됩니다. `color`는 `#F28AAF`와 같은 6자리 RGB입니다. `prices`는 `[]`여도 됩니다. 각 가격에 `productID`, `currency`, `unitPriceMinor`가 필요하며 기존 유형을 참조해야 합니다. 같은 소속 안에서 유형·통화 조합은 중복될 수 없습니다.

`isArchived`는 선택 불리언이며 `true`만 보관 상태를 뜻합니다. 이 필드가 없는 옛 백업도 가져올 수 있고 버전은 `1`을 유지합니다. 활성 소속은 멤버와 그룹도 보관되지 않아야 합니다. 보관 자료도 유효해야 합니다. 백업을 직접 정리할 때는 과거 구매가 참조하는 멤버, 그룹, 소속 관계를 남겨 두세요.

| `records` 필드 | 조건과 의미 |
| --- | --- |
| `id` | 필수. 고유 구매 ID. 새 구매에는 새 ID를 사용하며 UUID 권장 |
| `date` | 필수. 유효한 그레고리력 날짜. 엄격한 `yyyy-MM-dd` 형식. 예: `2026-10-14` |
| `memberID`, `groupID`, `productID` | 필수. 같은 파일의 멤버·그룹·유형 참조 및 해당 소속 관계 필요 |
| `quantity` | 필수. 양의 정수 수량 |
| `unitPriceMinor` | 필수. 통화 최소 단위의 0 이상 정수 단가 |
| `currency` | 필수. 아래 표의 대문자 통화 코드 |
| `memberNameSnapshot`, `groupNameSnapshot`, `productNameSnapshot` | 필수. 구매 당시 이름. 공백만으로 작성 불가 |
| `colorSnapshot` | 필수. 구매 당시 6자리 RGB 대표 색상 |
| `eventID` | 선택. 같은 파일의 `events` ID 참조 |
| `eventNameSnapshot`, `citySnapshot`, `venueSnapshot`, `addressSnapshot`, `note` | 선택. 구매 당시 행사·도시·공연장·주소·메모 |

구매 날짜는 달력 날짜로 저장되어 이후 시간대 변경에도 이동하지 않습니다. 행사 날짜와 구매 날짜는 달라도 됩니다. 프로필 사진 필드에는 파일 경로가 아닌 Base64로 인코딩한 JPEG 데이터를 넣습니다.

## 금액 정밀도와 제한

총액은 `quantity × unitPriceMinor`이며 정수 연산을 사용합니다. 화면에 일반 가격을 입력하면 최소 단위로 변환됩니다. 허용 소수 자릿수를 초과하면 거부하며 임의로 반올림하지 않습니다. 숫자와 소수점을 사용하고 통화 기호나 천 단위 구분자는 넣지 마세요. JSON 금액은 정수만 허용됩니다.

| 통화 | 소수 자릿수 | 화면 가격 예 | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`, `KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`, `HKD`, `USD`, `THB`, `IDR`, `MYR` | 2 | `100.00` | `10000` |

앱의 현재 구현 기준이며 `IDR`과 `TWD`도 최소 단위 두 자릿수를 유지합니다. 구매별 곱셈, 수량 합계, 통화별 금액 합계에서 정수 오버플로를 검사합니다. JSON 텍스트와 인코딩된 수첩은 `20 × 1024 × 1024`바이트(20 MiB)까지입니다. 가져오는 프로필 사진은 디코딩 후 `2 × 1024 × 1024`바이트(2 MiB)까지이며 JPEG 구조도 검사합니다. 사진 보관함 원본은 10 MiB까지이고 저장 전 긴 변을 최대 512픽셀로 줄여 JPEG로 변환합니다.

## 가져오기·병합·백업

수첩 상단에서 “수첩 관리”를 열고 “백업”을 선택하여 JSON/텍스트 파일을 하나 이상 선택하거나 JSON을 붙여 넣고 미리보기를 검증한 뒤 가져오기를 확정합니다. 여러 파일은 먼저 병합한 뒤 미리 봅니다. 빈 파일, 자료가 없는 문서, 잘못된 필드, 충돌은 가져오기를 차단합니다. 각 파일에 모든 참조 자료가 있어야 하며 현재 수첩의 멤버나 그룹으로 누락을 보완할 수 없습니다. 붙여 넣은 내용을 바꾸면 이전 미리보기가 무효가 됩니다.

유효한 가져오기는 수정하지 않은 예시 수첩을 대체합니다. 그 외에는 다음 병합 규칙을 사용합니다.

- 그룹·멤버·소속·유형·행사를 `id`로 갱신하거나 추가합니다. 새 파일에 없는 기존 자료는 유지합니다. 가져오기로 보관 표시도 갱신할 수 있습니다.
- 구매는 `id`로 중복을 제거합니다. 동일 기록을 다시 가져와도 이중 집계하지 않습니다. 같은 ID의 내용이 다르면 오류로 전체 가져오기를 취소합니다. 구매 수정은 앱에서 하고 새 구매는 새 ID를 사용하세요.
- 병합 전후 전체 문서의 소속 고유성, 참조, 날짜, 스냅샷, 금액, 크기를 검증하며 실패하면 원래 수첩을 유지합니다.

내보내기에는 전체 수첩, 보관 자료, 과거 스냅샷, 가격, 프로필 사진이 포함됩니다. 복원은 병합이며 기존 구매 수정을 되돌리지 않습니다. 수정된 기록과 같은 ID지만 내용이 다른 옛 백업 기록은 충돌합니다. 이전하거나 자료를 보관할 수 있도록 내보낸 파일을 잘 저장하세요.

## 관리, 최애 멤버와 시스템 화면 모드

- 0.4.0(build 10)에서는 수첩 상단과 설정→데이터 관리에서 “수첩 관리”를 엽니다. “기록 관리”, “자료 정리”, “백업”이 있으며 기존 JSON 가져오기, 미리 보기, 전체 내보내기는 “백업”에 유지됩니다. 설정에는 “일기 관리”도 있습니다.
- 날짜 범위, 멤버, 그룹, 종류, 통화, 행사, 검색 조건을 조합한 뒤 개별 다중 선택, 현재 결과 전체 선택, 선택 해제를 할 수 있습니다. 조건을 변경하면 선택이 해제되며 결과가 없으면 삭제할 수 없습니다. 확인 창에 선택한 기록 수, 총수량, 통화별 금액을 표시합니다. 취소하면 유지하고, 명시적으로 확인해야 선택한 기록만 삭제하여 통계를 갱신합니다.
- “모든 물판 기록 삭제”는 현재 조건과 관계없이 수첩 전체에 적용하며 전체 기록 수, 수량, 통화별 금액을 다시 확인합니다. 그룹, 멤버, 종류, 행사 자료와 일기는 유지되어 새 기록을 추가할 수 있습니다.
- “자료 정리”에서 멤버 또는 그룹을 검색하고 여러 개 선택할 수 있습니다. 멤버 삭제는 모든 소속을 보관 처리하고, 그룹 삭제는 해당 그룹과 소속만 보관 처리하여 다른 그룹의 겸임 소속은 유지합니다. 과거 구매, 스냅샷, 통계는 남으며 과거 기록도 편집할 수 있습니다. 취소하면 보관 처리하지 않고 유효한 백업을 가져와 자료를 복원할 수 있습니다.
- “멤버와 종류”의 멤버 편집에서 “최애 멤버”를 개별 설정하거나 해제합니다. 설정은 멤버 ID에 속하며 모든 겸임 소속이 공유합니다. 구매 멤버 선택 상단에 최애를 표시하고 각 소속의 색상과 가격은 독립적으로 유지합니다. 아래에는 전체 그룹별 목록이 남습니다. 새 기록은 사용 가능한 최애 소속을 우선 선택하며 기존 멤버 연결도 최애를 먼저 표시합니다. 보관 처리된 멤버나 소속은 최애 바로 선택에서 제외됩니다.
- 멤버의 `isFavorite`는 선택적 Bool이며 `true`만 최애입니다. `false`, 생략, `null`은 최애가 아닙니다. 기존 JSON도 가져올 수 있고 `schemaVersion`은 `1`을 유지합니다. 전체 백업에 설정을 저장하며 멤버 ID로 자료를 병합할 때 갱신합니다.
