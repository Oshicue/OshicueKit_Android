# 日志使用与备份

[简体中文](DIARY.zh-CN.md) | [繁體中文](DIARY.zh-Hant.md) | [繁體粵語](DIARY.zh-HK.md) | [English](DIARY.en.md) | [日本語](DIARY.ja.md) | [한국어](DIARY.ko.md) | [ไทย](DIARY.th.md) | [Bahasa Indonesia](DIARY.id.md) | [Bahasa Melayu](DIARY.ms.md)

日志用于记录演出、物贩和远征经历。原稿保存在本机，可持续编辑，再复制或导出为发布用文本。首次使用没有预置日志；模板中的虚构示例需主动导入。

## 新建与整理

1. 在第三个「日志」页点击加号，填写标题和多行正文。正文可保留自己输入的 Markdown，编辑器不提供 Markdown 渲染预览。
2. 填写「摘要与要点」。列表卡片优先展示摘要，摘要为空时展示正文开头，并最多显示三个标签。
3. 标签以逗号、顿号、分号或换行分隔，允许半角及全角分隔符。自动去除首尾空白和 `#`／`＃`，忽略大小写去重；日文清浊音和不同重音仍保留为不同标签。
4. 在「活动资料」选择已有手账活动，带入名称、公历日期、城市、场馆和地址；缺少有效日期时保留当前所选日期。也可手动填写，或在编辑页新增手账活动。
5. 选择「草稿」或「已整理」；状态只用于本地整理与筛选，不表示已发布。

活动资料是日志自己的快照。修改或删除手账活动不会改写已保存日志；再次选入活动时才更新快照。切回手动填写只解除活动编号关联，不清空已带入资料。日志可以独立使用，场馆和地址由用户填写或从手账带入。

列表按活动日期从近到远分组，同一天按最近修改时间排序。搜索覆盖标题、正文、摘要、标签及活动名称、日期、城市、场馆、地址；多个空白分隔的词必须全部匹配，匹配可分布在不同字段。可筛选全部、草稿、已整理。

## 自动保存与删除

停止修改约 0.5 秒后自动保存。点击「完成」「关闭」、进入后台或离开编辑页时会立即尝试保存。保存失败时显示错误与重试入口；「完成」「关闭」仅在保存成功后退出，失败写入不会替换已保存数据。

仅打开空表单、只更改日期或状态不会建立新日志；标题、正文、摘要、标签或活动名称、城市、场馆、地址中有实际内容时才开始保存。已保存日志清空文字后仍可保留。每篇日志始终需要有效活动日期。

已保存日志的编辑页底部有「删除日志」，操作需要确认。删除仅移除本机日志，不删除手账活动、消费记录或已导出的副本。

## 文本导出与完整备份

「准备发布」会先保存当前修改，再展示文本。可复制 Markdown 或纯文本、导出 `.md`／`.txt`，或打开 iOS 系统分享面板。文本含标题、活动资料、标签、摘要和正文；正文、摘要保留原有换行。Markdown 导出会转义标题和活动资料中的内联特殊字符，正文与摘要保持原文。分享目标和后续操作由用户选择，App 不连接社交账号或自动发布。

从日志页右上角或第四个「设置」页打开「日志管理」，切换至「备份」，「导出全部日志」通过系统文件面板保存完整 JSON。JSON 保留编号、状态、标签数组、活动快照以及创建和修改时刻，适合再次导入；`.md`／`.txt` 用于阅读和分享。备份需要主动导出及保管，不是自动云备份；继续编辑不会更新已导出的文件。

## JSON 格式

[diary-template.json](../Templates/diary-template.json) 是虚构示例。替换为实际记录，为新增日志分配新的唯一编号；文件采用 UTF-8。顶层必填 `schemaVersion`（整数 `1`）及 `entries`（数组）。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `id` | 字符串 | 必填、非空且唯一，推荐 UUID。 |
| `title` | 字符串 | 必填，草稿可为 `""`。 |
| `body` | 字符串 | 必填，完整正文；JSON 换行写为 `\n`，可为 `""`。 |
| `summary` | 字符串 | 必填，摘要与要点，可为 `""`。 |
| `tags` | 字符串数组 | 必填，无标签写 `[]`。 |
| `status` | 字符串 | 必填，只能为 `draft` 或 `ready`。 |
| `event` | 对象 | 必填，字段见下表。 |
| `createdAt` | 字符串 | 必填，带时区的 ISO 8601 创建时刻。 |
| `updatedAt` | 字符串 | 必填，修改时刻，不得早于 `createdAt`。 |

| `event` 字段 | 类型 | 要求 |
| --- | --- | --- |
| `ledgerEventID` | 字符串或 null | 可选，可省略或为 `null`；字符串须非空，不要求活动仍在手账中。 |
| `name` | 字符串 | 必填，活动名称，可为 `""`。 |
| `date` | 字符串 | 必填，有效公历日期，严格为 `yyyy-MM-dd`，如 `2026-10-14`。 |
| `city` | 字符串 | 必填，城市，可为 `""`。 |
| `venue` | 字符串 | 必填，场馆，可为 `""`。 |
| `address` | 字符串 | 必填，完整地址，可为 `""`。 |

`event.date` 是年月日，没有时区或时分秒。创建和修改时刻是绝对时间，导出为毫秒精度，例如 `2026-01-01T00:00:00.000Z`。导入也接受明确 UTC 偏移，例如 `2026-01-01T09:00:00.000+09:00`；不能省略 `Z` 或偏移。活动日期可早于补写日志的创建时刻。日志备份不要求成员、团体或手账备份。

## 导入与冲突

在「日志管理」的「备份」中选择一个或多个 UTF-8 JSON 文件，或粘贴 JSON 后点击「检查并预览」。预览列出新增和已存在数量，确认后才写入。

- 同一编号且全部内容相同的日志会去重；创建、修改时刻按毫秒精度比较。
- 同一编号内容不同，包括正文、摘要、标签、状态、活动资料或时间戳不同，整次导入停止，原数据保留。修改旧日志请在 App 内编辑；保留另一版本请使用新编号。
- 导入只增加新日志，原数据中未在文件出现的日志继续保留。多个所选文件之间也执行相同冲突规则。
- 每份输入及合并后数据的上限为 20 MiB（`20 * 1024 * 1024` 字节）。手动编辑也受此限制。
- 重复编号、缺失字段、类型错误、非法状态、日期、时间戳或无效 UTF-8 会提示错误，字段错误附位置；未通过校验不会写入。

导入入口拒绝空日志集合。内部存储和导出允许 `entries: []`，表示当前没有日志。

## 本机数据与语言

日志独立、原子保存到 Application Support 内的 `OshicueKit/diary.json`，重启时读取。若原文件损坏，首次成功替代前会在同目录保留 `diary.recovery-<UUID>.json` 恢复副本。该机制不替代用户备份。

设置中的语言选择统一作用于时间表、手账、日志与设置；日期显示随语言变化，正文、活动名称及地址等用户内容保持原样。

## 日志管理与系统外观

- 0.4.0（build 10）从日志页右上角或设置→数据管理打开「日志管理」，页面提供「记录管理」与「备份」。JSON 的导入、预览及导出全部日志功能保留在「备份」中。
- 按状态、活动日期范围和搜索组合筛选，逐篇多选、全选当前结果或清除选择。更改筛选清空选择；删除前确认篇数及正文、摘要的删除范围，取消不删除。确认仅移除所选日志；其他日志、手账及时间表保留，删除结果会保存到本机。
- 日志列表、编辑器、发布准备、管理、备份和设置均跟随系统浅色／深色外观，系统切换即时生效，已保存正文及活动快照保持原内容。
