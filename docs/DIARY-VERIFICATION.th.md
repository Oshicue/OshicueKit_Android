# คู่มือตรวจสอบบันทึกประจำวันและการตั้งค่าร่วม

[简体中文](DIARY-VERIFICATION.md) | [繁體中文](DIARY-VERIFICATION.zh-Hant.md) | [繁體粵語](DIARY-VERIFICATION.zh-HK.md) | [English](DIARY-VERIFICATION.en.md) | [日本語](DIARY-VERIFICATION.ja.md) | [한국어](DIARY-VERIFICATION.ko.md) | [ไทย](DIARY-VERIFICATION.th.md) | [Bahasa Indonesia](DIARY-VERIFICATION.id.md) | [Bahasa Melayu](DIARY-VERIFICATION.ms.md)

หน้านี้อธิบายขอบเขตการทดสอบของคลังโค้ดปัจจุบันและวิธีทำซ้ำ ไม่ได้ยืนยันว่าการทดสอบผ่านในสภาพแวดล้อมปัจจุบัน โครงการตั้งค่าเป็น 0.4.0 / build 10 รองรับขั้นต่ำ iOS 17 และ Swift Package ส่วนหลักรองรับ macOS 14 ด้วย ผลที่รันจริงควรบันทึกคอมมิต เวอร์ชัน Xcode อุปกรณ์ และผลลัพธ์การทดสอบ

## การทดสอบส่วนหลัก

[DiaryTests.swift](../Tests/DiaryTests.swift) กำหนดการทดสอบบันทึกประจำวัน 18 รายการ รันจากโฟลเดอร์หลักของโครงการ:

```sh
swift test --filter DiaryTests
```

| ขอบเขต | สิ่งที่ตรวจสอบ |
| --- | --- |
| ฉบับร่างและสำเนาข้อมูลงาน | บันทึกว่างและฉบับร่างที่ยังไม่ครบใช้ได้ ข้อมูลงานเป็นอิสระ หากไม่มีวันที่งานที่ถูกต้องให้ใช้วันที่ที่เลือก |
| ข้อความและเวลา | เนื้อหา Unicode ยาว ช่องว่าง และขึ้นบรรทัดใหม่คงเดิมหลังแปลงไปกลับ ตัดซ้ำด้วยความละเอียดมิลลิวินาที ออฟเซ็ตเขตเวลาแทนเวลาสัมบูรณ์เดียวกัน |
| รวมและข้อขัดแย้ง | ตัดบันทึกเหมือนกันและเพิ่มบันทึกใหม่ รหัสเดียวกันที่เนื้อหา สรุป แท็ก สถานะ ที่อยู่ หรือเวลาแก้ไขต่างกันทำให้ปฏิเสธทั้งชุด |
| ตรวจข้อมูล | รหัสซ้ำหรือว่าง วันที่และลำดับเวลาผิด เวอร์ชัน ช่องข้อมูลบังคับ ชนิดข้อมูล เวลา JSON และ UTF-8 ไม่ถูกต้อง ขีดจำกัด 20 MiB |
| จัดระเบียบและส่งออก | แบ่งแท็กและตัดซ้ำโดยคงความต่างเสียงญี่ปุ่นและเครื่องหมายกำกับเสียง ค้นหลายคำข้ามช่องข้อมูล ข้อความธรรมดาและ Markdown มีข้อมูลงาน สรุป เนื้อหาเดิม และใส่อักขระหลีกในชื่อ |

พฤติกรรมเรื่องข้อมูลซ้ำ ข้อขัดแย้ง ขนาดที่จัดเก็บ และการส่งออกในการทดสอบอ้างอิงโค้ดปัจจุบัน หากจำนวนหรือขอบเขตการทดสอบเปลี่ยน ต้องอัปเดตหน้านี้ด้วย

## การทดสอบหน้าจอเนทีฟ

[DiaryUITests.swift](../UITests/DiaryUITests.swift) กำหนดการทดสอบ 5 รายการ:

1. เลือกงานจากสมุดบันทึก กรอกเนื้อหาหลายบรรทัด สรุปและแท็ก แล้วเข้าเบื้องหลัง เริ่มแอปใหม่และตรวจข้อมูลงานกับข้อความ ยืนยันว่ามีเพียงหนึ่งบันทึก
2. ดูตัวอย่างและนำเข้า JSON นำเข้าซ้ำแล้วตัดซ้ำ เปลี่ยนเนื้อหาใต้รหัสเดิมแล้วถูกปฏิเสธ และต้นฉบับยังอยู่หลังเริ่มใหม่
3. ยกเลิกและยืนยันในหน้าต่างลบ หลังเริ่มใหม่ยังถูกลบ แต่งานในสมุดบันทึกและรายการซื้อยังอยู่
4. เปิดจัดการบันทึกประจำวันจากแท็บตั้งค่าที่สี่แล้วเลือกสำรองข้อมูล เปลี่ยนเป็นอังกฤษแล้วมีผลข้ามส่วนต่าง ๆ โดยเนื้อหาบันทึกเดิมยังอยู่
5. ตรวจชื่อบันทึก ปุ่มสร้างใหม่ แท็บตั้งค่าที่สี่ และสถานะไม่มีบันทึกในแต่ละภาษา รวมเก้าภาษา รายการนี้ไม่ได้หมายถึงข้อความทุกจุดผ่านการตรวจด้วยคนแล้ว

แสดงรายการเครื่องจำลองที่ใช้ได้ในเครื่องก่อน แล้วแทน `<SIMULATOR_ID>` ด้วยรหัสอุปกรณ์จริง:

```sh
xcrun simctl list devices available
xcodebuild test -project OshicueKit.xcodeproj -scheme OshicueKit -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' -only-testing:OshicueKitUITests/DiaryUITests
```

ใน Debug การทดสอบใช้ `OSHICUE_UI_TESTS=1` เพื่อใช้ไฟล์แยก `ui-test-diary.json` ส่วนการคงข้อมูลเมื่อเริ่มใหม่ใช้ `OSHICUE_PRESERVE_UI_DATA=1` ตัวแปรเหล่านี้ใช้แยกการทดสอบ ไม่ใช่ช่องทางสำรองข้อมูลของผู้ใช้

## ตรวจภาษา ตรวจด้วยคน และหลักฐาน

รันสคริปต์ต่อไปนี้บน macOS เพื่อตรวจชุดคีย์ ค่าที่ไม่ว่าง ตัวแทนค่า และการอ่าน `.strings` ของเก้าภาษา สคริปต์ไม่ประเมินความหมายคำแปลหรือการจัดหน้าจอ:

```sh
python3 scripts/verify-localizations.py
```

การตรวจด้วยคนควรรวมการบันทึกอัตโนมัติและลองใหม่หลังล้มเหลว การเลือกงานและสำเนาอิสระ การค้นหาและกรอง การยกเลิกและยืนยันลบ รวมหลายไฟล์และข้อขัดแย้ง ปฏิเสธสำรองว่าง บันทึกและอ่าน `.md`／`.txt`／JSON จริง ยกเลิกการแชร์ของระบบ และข้อความยาวกับวันที่ในเก้าภาษา อย่าเลือกผู้รับแชร์โดยไม่ได้รับอนุญาต

ภาพ [รายการบันทึก](../screenshots/diary-list.png), [ตัวแก้ไข](../screenshots/diary-editor.png), [ข้อมูลงาน](../screenshots/diary-editor-event.png), [ตัวอย่างสำรอง](../screenshots/diary-backup-preview.png), [ข้อความขัดแย้ง](../screenshots/diary-backup-conflict.png) และ [การตั้งค่าร่วม](../screenshots/global-settings.png) ที่มีอยู่เป็นภาพอ้างอิงในคลังโค้ด ไม่ยืนยันว่าบิลด์ปัจจุบันผ่าน การส่งถึงผู้รับ การติดตั้งเครื่องจริง กระบวนการเผยแพร่ และการกู้คืนเมื่อบันทึกอัตโนมัติล้มเหลว ตัดสินจากการทดสอบส่วนหลักเพียงอย่างเดียวไม่ได้ ต้องบันทึกผลแยกตามที่ทำจริง

## ทดสอบซ้ำการจัดการ สมาชิกโปรดและรูปลักษณ์ 0.4.0

ต่อไปนี้คือข้อกำหนดทดสอบและขอบเขตตรวจซ้ำที่เพิ่มสำหรับ 0.4.0 / build 10 ไม่ได้ยืนยันว่าได้รันและผ่านทุก UI test ครั้งนี้ ให้บันทึกผ่าน ล้มเหลวหรือยังไม่รันตามผลจริง การตรวจชุดสีก็ไม่แทนการตรวจแต่ละหน้าด้วยตา

| ไฟล์ทดสอบ | จำนวน | ขอบเขตที่เพิ่ม |
| --- | --- | --- |
| [DiaryManagementTests.swift](../Tests/DiaryManagementTests.swift) | 4 | กรองสถานะ/วันที่/ค้นหาร่วมกัน ช่วงผิด ลบบันทึกที่เลือกโดยเก็บเนื้อหาอื่นและข้อมูลงาน ไฟล์สำรองบันทึกว่าง |
| [DataManagementUITests.swift](../UITests/DataManagementUITests.swift) | 6 | กรองซื้อและเลือกหลายรายการ ยกเลิก/ยืนยัน เปลี่ยนกรองล้างเลือก ลบทุกสกุลเงิน ลบบันทึกหลายฉบับและแบบฟอร์มสำรองในหน้าจัดการของการตั้งค่า เลือกข้อมูลอ้างอิงหลายรายการ ยกเลิก/ยืนยันการเก็บถาวรและเก็บประวัติซื้อไว้ |
| [DataManagementFailureUITests.swift](../UITests/DataManagementFailureUITests.swift) | 2 | ใช้ `OSHICUE_FAIL_BATCH_DELETE=1` จำลองความล้มเหลวในการบันทึกจริงกับข้อมูลทดสอบ Debug แยกต่างหาก ตรวจว่ารายการเดิม เนื้อหาบันทึกและการเลือกปัจจุบันยังอยู่ ข้อมูลไม่เปลี่ยนหลังเปิดใหม่ และเลือกอีกครั้งเพื่อลองลบหลังปิดการจำลองความล้มเหลว |
| [AppearanceUITests.swift](../UITests/AppearanceUITests.swift) | 5 | ชุดสี UIKit แบบไดนามิกจริง ความต่างสีข้อความและตัวควบคุมที่เลือกในสองโหมด พื้นหลังสถานที่ เพิ่มความต่างสีและอ่านสีสมาชิกได้ โดยไม่ได้กดใช้งานหน้าแอป |

```sh
swift test --filter Diary
xcodebuild test -project OshicueKit.xcodeproj -scheme OshicueKit -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' -only-testing:OshicueKitUITests/DataManagementUITests -only-testing:OshicueKitUITests/AppearanceUITests -only-testing:OshicueKitUITests/DataManagementFailureUITests
```

## ขั้นตอนตรวจซ้ำด้วยคนเพิ่มเติม

- เปิดหน้าจัดการทั้งสองจากการตั้งค่าและตรวจนำเข้า/ส่งออกเดิมในสำรอง รวมตัวกรอง เลือกบางผลและตรวจจำนวนยืนยัน ยกเลิกก่อนแล้วค่อยยืนยันและเปิดใหม่ ยอดซื้อต้องแยกสกุลเงินและเปลี่ยนกรองต้องล้างการเลือก
- เลือกเก็บถาวรสมาชิกหลายสังกัดกับหนึ่งวง ตรวจขอบเขต สังกัดอื่นและแก้ประวัติ ลบซื้อทั้งหมดแล้วข้อมูลอ้างอิงกับบันทึกยังอยู่ เลือกลบบันทึกตามสถานะ วันที่ ค้นหาและตรวจเนื้อหาที่ไม่เลือกกับส่วนอื่น
- ตั้งสมาชิกโปรดแล้วเปิดผ่านอีกสังกัด ตรวจการตั้งค่าร่วม ส่วนบนหน้าเลือก ราคาตามสังกัดและค่าเริ่มใหม่ ตรวจการยกเลิก เก็บถาวร ส่งออกและนำเข้ากลับ JSON เก่าที่ไม่มี `isFavorite` ต้องไม่โปรดและ `schemaVersion` ยังคง `1`
- เปลี่ยนโหมดสว่าง/มืดของระบบ ตรวจสี่ส่วน รายละเอียด แก้ไข เลือก จัดการและสำรอง รวมถึงข้อความใหญ่ ป้ายยาวเก้าภาษา รูปสมาชิก สี ยอดเงิน ปุ่มที่เลือกและข้อผิดพลาด บันทึกอุปกรณ์กับรุ่นระบบ ไม่ใช้ภาพเก่าแทนผลครั้งนี้
