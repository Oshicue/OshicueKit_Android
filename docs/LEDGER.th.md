# คู่มือสมุดบันทึกและรูปแบบข้อมูล

[简体中文](LEDGER.zh-CN.md) | [繁體中文](LEDGER.zh-Hant.md) | [繁體粵語](LEDGER.zh-HK.md) | [English](LEDGER.en.md) | [日本語](LEDGER.ja.md) | [한국어](LEDGER.ko.md) | [ไทย](LEDGER.th.md) | [Bahasa Indonesia](LEDGER.id.md) | [Bahasa Melayu](LEDGER.ms.md)

สมุดบันทึกใช้ปฏิทินบันทึกการซื้อสินค้า จัดการวง สมาชิก ความสัมพันธ์การเป็นสมาชิก สีประจำตัวและราคาเริ่มต้น พร้อมจัดอันดับจำนวนและยอดใช้จ่าย ข้อมูลเก็บไว้ในอุปกรณ์ และไฟล์สำรองสมุดบันทึกแยกจากตารางเวลาและไดอารี

## เริ่มใช้งาน

1. เพิ่มวงและสมาชิกใน「สมาชิกและประเภท」หากสมาชิกอยู่หลายวง ให้ใช้「เชื่อมโยงสมาชิกเดิม」เพื่อเพิ่มความสัมพันธ์โดยคง ID สมาชิกเดียวกัน ชื่อเหมือนกันแต่ ID ต่างกันจะไม่รวมเป็นคนเดียวโดยอัตโนมัติ
2. ตั้งสีและราคาต่อหน่วยเริ่มต้นแยกตามความสัมพันธ์แต่ละวง ประเภทเริ่มต้นคือเชกิ เชกิ WIDE และถ่ายรูปด้วยมือถือ สามารถเพิ่มประเภทและราคาหลายสกุลเงินให้ประเภทเดียวกันได้ ชื่อและรูปสมาชิกใช้ร่วมกันทุกวง
3. แตะ「＋」เลือกวันที่ วงของสมาชิก ประเภท จำนวน สกุลเงินและราคาต่อหน่วยจริง เมื่อเปลี่ยนความสัมพันธ์ ประเภทหรือสกุลเงิน ระบบจะเติมราคาเริ่มต้นที่ตรงกันใหม่ หากไม่มีราคาเริ่มต้นต้องกรอกเอง จำนวนต้องเป็นจำนวนเต็มบวก ราคาต่อหน่วยเป็นศูนย์ได้
4. งาน เมือง สถานที่ ที่อยู่และหมายเหตุไม่จำเป็นต้องกรอก สร้างงานในสมุดบันทึกหรือเลือกงานและสถานที่จากตารางเวลาเพื่อคัดลอกเป็นงานในสมุดบันทึกได้ การแก้ตารางเวลาภายหลังจะไม่อัปเดตสมุดบันทึกอัตโนมัติ
5. ตัวเลขในปฏิทินคือจำนวนสินค้ารวมของวัน ไม่ใช่จำนวนรายการ การ์ดรายเดือนแสดงจำนวนและยอดใช้จ่ายแยกสกุลเงิน เลือกวันที่เพื่อดูสรุปสมาชิกแยกตามวงและแต่ละรายการ

จำนวนหมายถึงหน่วยของประเภทที่เลือก เช่น รูปนับเป็นใบ และประเภทบัตรที่เพิ่มเองนับเป็นจำนวนบัตรได้

## แก้ไข ลบ และข้อมูล ณ เวลาที่ซื้อ

แตะการ์ดสมาชิกใต้วันที่ หากมีการซื้อรายการเดียวจะเปิดหน้าแก้ไขทันที หากมีหลายรายการต้องเลือกก่อน หรือขยายรายการซื้อแล้วเลือกแก้ไขได้ แบบฟอร์มจะโหลดวันที่ ความสัมพันธ์ ประเภท จำนวน ราคาและข้อมูลเสริมเดิม การบันทึกแก้เฉพาะรายการที่เลือก การลบรายการซื้อในหน้าแก้ไขต้องยืนยัน และจะหักจำนวนกับยอดเงินของรายการนั้น

ใน「สมาชิกและประเภท」แตะสมาชิกเพื่อแก้ข้อมูล หรือแตะดินสอข้างชื่อวงเพื่อแก้วง การลบทั้งสองแบบต้องยืนยัน:

- ลบสมาชิก: เก็บสมาชิกและความสัมพันธ์ของสมาชิกในทุกวงไว้ในสถานะเก็บถาวร
- ลบวง: เก็บวงและความสัมพันธ์ของวงนั้นไว้ในสถานะเก็บถาวร สมาชิกที่อยู่ในวงอื่นด้วยยังใช้ได้ในวงอื่น

ข้อมูลที่เก็บถาวรยังอยู่ในไฟล์สำรอง การซื้อเดิม ชื่อ สี ราคาและสถิติยังคงอยู่ รายการใหม่หรือการเปลี่ยนความสัมพันธ์ต้องใช้ความสัมพันธ์ที่ยังใช้งานอยู่ ประวัติการซื้อยังแก้ไขได้โดยคงความสัมพันธ์เดิมที่ถูกลบ ตัวเลือกจะแสดงว่าลบแล้ว หน้าจัดการข้อมูลไม่มีปุ่มคืนค่า แต่การนำเข้าไฟล์สำรองที่มีข้อมูลใช้งานอยู่ด้วย ID เดิมสามารถคืนข้อมูลรายการได้ โดยต้องผ่านการตรวจสอบการรวมทั้งหมด

การเปลี่ยนชื่อ สีหรือราคาเริ่มต้นในข้อมูลหลักไม่แก้การซื้อที่บันทึกแล้ว ขณะแก้การซื้อ หากคงความสัมพันธ์เดิมจะคงชื่อสมาชิก ชื่อวงและสี ณ เวลาซื้อ หากคงประเภทเดิมจะคงชื่อประเภท ณ เวลาซื้อ เมื่อเปลี่ยนความสัมพันธ์หรือประเภทจะสร้างข้อมูล ณ เวลาซื้อชุดใหม่ที่ตรงกัน ราคาจริงและข้อมูลงานบันทึกตามแบบฟอร์ม ระบบตรวจสอบสมุดบันทึกทั้งหมดก่อนบันทึกลงอุปกรณ์ในครั้งเดียว หากล้มเหลวจะไม่ใช้การเปลี่ยนแปลงเพียงบางส่วน

## สถิติ

ดูสถิติรายวัน เดือน ปีหรือทั้งหมด กรองตามประเภทและวง และจัดอันดับแบบรวมต่อสมาชิก แยกสมาชิกตามวง หรือแยกวงได้ จำนวนสมาชิกนับจาก `memberID` ที่ไม่ซ้ำในรายการหลังกรอง วงที่เก็บถาวรยังใช้กรองประวัติได้

อันดับจำนวนรวมหน่วยจากทุกสกุลเงินได้ แต่อันดับยอดใช้จ่ายต้องเลือกสกุลเงินเดียว ระบบไม่รวมเงินต่างสกุลหรือแปลงค่าเงินอัตโนมัติ สรุปแสดงจำนวนตามประเภทและยอดแยกสกุลเงิน อันดับร่วมใช้รูปแบบ `1、1、3` และเรียงกรณีเท่ากันตาม ID อย่างสม่ำเสมอ สัดส่วนใช้จำนวนหรือยอดใช้จ่ายสกุลเดียวในช่วงที่กรองเป็นตัวหาร ถ้ายอดรวมเป็นศูนย์สัดส่วนก็เป็นศูนย์ ชื่อและสีในอันดับใช้ข้อมูล ณ เวลาซื้อจากรายการล่าสุดในช่วงกรอง หากวันเดียวกันจะเลือกตามลำดับ ID รายการ

## สมุดบันทึกตัวอย่าง

เมื่อเปิดครั้งแรกโดยไม่มีไฟล์บันทึก ระบบจะโหลดข้อมูลสมมติและบันทึกทันที: 2 วง สมาชิก 3 คน ความสัมพันธ์ 4 รายการ ประเภท 3 แบบ งาน 1 งานและการซื้อ 5 รายการ รวม 16 หน่วย วันที่ใช้วันปฏิทิน `Asia/Shanghai` ตอนสร้างและสองวันก่อนหน้า วันสร้างมีจำนวน 10 หน่วย ไม่ยึดวันที่คงที่จากแม่แบบ และไม่มีป้ายระบุข้อมูลตัวอย่าง

สมุดบันทึกเดิมอ่านข้อมูลที่เก็บไว้ การเปิดใหม่ไม่คืนตัวอย่างที่แก้หรือลบแล้ว การโหลดตัวอย่างใช้ได้เฉพาะสมุดบันทึกว่างหรือตัวอย่างที่ยังไม่แก้ ว่างหมายถึงไม่มีวง สมาชิก ความสัมพันธ์ งานและการซื้อ โดยประเภทต้องว่างหรือตรงกับสามประเภทเริ่มต้นทุกประการ การเก็บข้อมูลถาวรอย่างเดียวไม่ทำให้สมุดบันทึกว่าง การนำเข้าครั้งแรกแทนตัวอย่างที่ยังไม่แก้ได้ แต่เมื่อบันทึกการแก้ตัวอย่างแล้วจะใช้กฎการรวม

## ฟิลด์ JSON

[ledger-template.json](../Templates/ledger-template.json) เป็นตัวอย่างนำเข้าที่แยกจากแม่แบบตารางเวลา ใช้ UTF-8 และ `schemaVersion` ต้องเป็น `1` ต้องมีอาร์เรย์ทั้งหกต่อไปนี้ หากไม่มีข้อมูลให้ใส่ `[]` ค่า `id` ต้องไม่ซ้ำภายในแต่ละอาร์เรย์ และ ID กับชื่อต้องไม่เป็นเพียงช่องว่าง

| อาร์เรย์ | ฟิลด์จำเป็น | ฟิลด์ไม่บังคับ |
| --- | --- | --- |
| `groups` | `id`, `name` | `isArchived` |
| `members` | `id`, `name` | `avatarJPEGBase64`, `isArchived`、`isFavorite` |
| `memberships` | `id`, `memberID`, `groupID`, `color`, `prices` | `isArchived` |
| `products` | `id`, `name` | ไม่มี |
| `events` | `id`, `name` | `date`, `city`, `venue`, `address` |
| `records` | ดูตารางถัดไป | ดูตารางถัดไป |

`memberships` อ้างสมาชิกและวงในไฟล์เดียวกัน คู่สมาชิกกับวงแต่ละคู่มีความสัมพันธ์ได้เพียงหนึ่งรายการ `color` เป็น RGB หกหลัก เช่น `#F28AAF` ส่วน `prices` เป็น `[]` ได้ แต่ราคาทุกรายการต้องมี `productID`, `currency`, `unitPriceMinor` และอ้างประเภทที่มีอยู่ คู่ประเภทกับสกุลเงินห้ามซ้ำภายในความสัมพันธ์เดียวกัน

`isArchived` เป็นบูลีนไม่บังคับ โดย `true` เท่านั้นหมายถึงเก็บถาวร ไฟล์สำรองเก่าที่ไม่มีฟิลด์นี้ยังนำเข้าได้และยังใช้เวอร์ชัน `1` ความสัมพันธ์ที่ใช้งานได้ต้องมีสมาชิกและวงที่ไม่ถูกเก็บถาวรด้วย ข้อมูลที่เก็บถาวรยังต้องถูกต้อง หากจัดไฟล์สำรองเองต้องคงสมาชิก วงและความสัมพันธ์ที่ประวัติการซื้ออ้างถึง

| ฟิลด์ `records` | ข้อกำหนดและความหมาย |
| --- | --- |
| `id` | จำเป็น ID การซื้อไม่ซ้ำ การซื้อใหม่ใช้ ID ใหม่ แนะนำ UUID |
| `date` | จำเป็น วันที่ปฏิทินเกรกอเรียนที่ถูกต้องตาม `yyyy-MM-dd` อย่างเคร่งครัด เช่น `2026-10-14` |
| `memberID`, `groupID`, `productID` | จำเป็น อ้างสมาชิก วงและประเภทในไฟล์เดียวกัน โดยมีความสัมพันธ์ที่ตรงกัน |
| `quantity` | จำเป็น จำนวนเต็มบวก |
| `unitPriceMinor` | จำเป็น ราคาต่อหน่วยเป็นจำนวนเต็มไม่ติดลบ ในหน่วยย่อยของสกุลเงิน |
| `currency` | จำเป็น รหัสสกุลเงินตัวพิมพ์ใหญ่จากตารางด้านล่าง |
| `memberNameSnapshot`, `groupNameSnapshot`, `productNameSnapshot` | จำเป็น ชื่อ ณ เวลาที่ซื้อ ห้ามมีเพียงช่องว่าง |
| `colorSnapshot` | จำเป็น สี RGB หกหลัก ณ เวลาที่ซื้อ |
| `eventID` | ไม่บังคับ อ้าง ID ใน `events` ของไฟล์เดียวกัน |
| `eventNameSnapshot`, `citySnapshot`, `venueSnapshot`, `addressSnapshot`, `note` | ไม่บังคับ งาน เมือง สถานที่ ที่อยู่และหมายเหตุ ณ เวลาที่ซื้อ |

วันที่ซื้อเก็บเป็นวันปฏิทิน การเปลี่ยนเขตเวลาภายหลังไม่เลื่อนรายการ วันที่งานต่างจากวันที่ซื้อได้ ฟิลด์รูปสมาชิกเป็นข้อมูล JPEG แบบ Base64 ไม่ใช่พาธไฟล์

## ความละเอียดของยอดเงินและข้อจำกัด

ยอดรวมคือ `quantity × unitPriceMinor` โดยคำนวณด้วยจำนวนเต็ม กรอกราคาปกติในหน้าจอแล้วระบบแปลงเป็นหน่วยย่อย หากเกินจำนวนทศนิยมที่อนุญาตจะถูกปฏิเสธ ไม่ปัดเศษเงียบ ๆ แนะนำให้ใช้ตัวเลขและจุดทศนิยม ไม่ใส่สัญลักษณ์เงินหรือตัวคั่นหลักพัน ยอดใน JSON ต้องเป็นจำนวนเต็ม

| สกุลเงิน | ตำแหน่งทศนิยม | ตัวอย่างราคาในหน้าจอ | `unitPriceMinor` |
| --- | --- | --- | --- |
| `JPY`, `KRW` | 0 | `2000` | `2000` |
| `CNY` | 2 | `80.50` | `8050` |
| `TWD`, `HKD`, `USD`, `THB`, `IDR`, `MYR` | 2 | `100.00` | `10000` |

นี่คือความละเอียดที่แอปใช้อยู่ `IDR` และ `TWD` คงหน่วยย่อยสองหลักเช่นกัน ระบบตรวจจำนวนเต็มล้นช่วงสำหรับผลคูณต่อรายการ จำนวนรวมและยอดรวมแต่ละสกุลเงิน ข้อความ JSON และสมุดบันทึกหลังเข้ารหัสจำกัด `20 × 1024 × 1024` ไบต์ (20 MiB) รูปที่นำเข้าแต่ละรูปหลังถอดรหัสจำกัด `2 × 1024 × 1024` ไบต์ (2 MiB) พร้อมตรวจโครงสร้าง JPEG รูปต้นฉบับจากคลังภาพจำกัด 10 MiB และก่อนบันทึกจะย่อด้านยาวไม่เกิน 512 พิกเซลแล้วแปลงเป็น JPEG

## นำเข้า รวม และสำรองข้อมูล

เปิด “จัดการสมุดบันทึก” ด้านบนของสมุดบันทึกแล้วเลือก “สำรองข้อมูล” เลือกไฟล์ JSON/ข้อความหนึ่งไฟล์หรือหลายไฟล์ หรือวาง JSON แล้วตรวจตัวอย่างก่อนยืนยันนำเข้า หลายไฟล์จะรวมก่อนแสดงตัวอย่าง ไฟล์ว่าง เอกสารไม่มีข้อมูล ฟิลด์ไม่ถูกต้องหรือข้อมูลขัดแย้งจะนำเข้าไม่ได้ ทุกไฟล์ต้องมีข้อมูลอ้างอิงทั้งหมด ไม่สามารถอาศัยสมุดบันทึกเดิมเติมสมาชิกหรือวงที่ขาดได้ การแก้ข้อความที่วางจะทำให้ตัวอย่างเดิมหมดอายุ

การนำเข้าที่ถูกต้องจะแทนสมุดบันทึกตัวอย่างที่ยังไม่แก้ กรณีอื่นใช้กฎการรวม:

- วง สมาชิก ความสัมพันธ์ ประเภทและงานอัปเดตหรือเพิ่มตาม `id` ข้อมูลเดิมที่ไม่มีในไฟล์ใหม่ยังอยู่ การนำเข้าสามารถอัปเดตสถานะเก็บถาวรได้
- การซื้อใช้ `id` ตัดรายการซ้ำ นำเข้ารายการเหมือนเดิมไม่เพิ่มยอดซ้ำ หาก ID เดียวกันแต่เนื้อหาต่างกันจะแสดงข้อผิดพลาดและยกเลิกการนำเข้าทั้งหมด แก้การซื้อในแอป และการซื้อใหม่ให้ใช้ ID ใหม่
- ตรวจเอกสารทั้งหมดก่อนและหลังรวม รวมถึงความสัมพันธ์ไม่ซ้ำ การอ้างอิง วันที่ ข้อมูล ณ เวลาซื้อ ยอดเงินและขนาด หากล้มเหลวสมุดบันทึกเดิมจะไม่เปลี่ยน

ไฟล์ส่งออกมีสมุดบันทึกทั้งหมด ข้อมูลเก็บถาวร ข้อมูล ณ เวลาซื้อ ราคาและรูปสมาชิก การคืนค่าคือการรวม ไม่ย้อนการแก้ซื้อเดิม รายการที่แก้แล้วจะขัดแย้งกับรายการในไฟล์สำรองเก่าที่ ID เดียวกันแต่ข้อมูลต่างกัน เก็บไฟล์ส่งออกไว้สำหรับย้ายอุปกรณ์หรือเก็บประวัติ

## การจัดการ สมาชิกโปรด และรูปลักษณ์ตามระบบ

- ใน 0.4.0 (build 10) ปุ่มด้านบนสมุดบันทึกและการตั้งค่า→จัดการข้อมูลเปิด “จัดการสมุดบันทึก” ซึ่งมี “จัดการรายการ” “จัดการข้อมูลสมาชิกและวง” และ “สำรองข้อมูล” การนำเข้า JSON ดูตัวอย่างและส่งออกทั้งหมดเดิมยังอยู่ใน “สำรองข้อมูล” การตั้งค่ายังมี “จัดการบันทึกประจำวัน”
- กรองรายการซื้อโดยรวมช่วงวันที่ สมาชิก วง ประเภท สกุลเงิน งาน และคำค้น แล้วเลือกหลายรายการทีละรายการ เลือกผลลัพธ์ปัจจุบันทั้งหมด หรือล้างการเลือก การเปลี่ยนตัวกรองจะล้างการเลือก และลบไม่ได้เมื่อไม่มีผลลัพธ์ ก่อนยืนยันจะแสดงจำนวนรายการ จำนวนชิ้นรวม และยอดแยกสกุลเงิน การยกเลิกไม่ลบ ต้องยืนยันชัดเจนจึงลบเฉพาะรายการที่เลือกและปรับสถิติ
- “ลบรายการซื้อทั้งหมด” ใช้กับสมุดบันทึกทั้งหมดโดยไม่ขึ้นกับตัวกรองปัจจุบัน และต้องยืนยันจำนวนรายการ จำนวนชิ้นและยอดแยกสกุลเงินอีกครั้ง ข้อมูลวง สมาชิก ประเภท งาน และบันทึกประจำวันยังอยู่เพื่อเพิ่มรายการใหม่
- “จัดการข้อมูลสมาชิกและวง” รองรับค้นหาและเลือกสมาชิกหรือวงหลายรายการ การลบสมาชิกเก็บถาวรทุกสังกัดของคนนั้น การลบวงเก็บถาวรเฉพาะวงและสังกัดในวงนั้น โดยสังกัดวงอื่นยังอยู่ ประวัติซื้อ สำเนาข้อมูล และสถิติยังอยู่และแก้ประวัติได้ การยกเลิกไม่เก็บถาวร และนำเข้าไฟล์สำรองที่ถูกต้องเพื่อคืนข้อมูลได้
- ตั้งหรือยกเลิก “สมาชิกโปรด” แยกในหน้าแก้สมาชิกของ “สมาชิกและประเภท” การตั้งค่าผูกกับรหัสสมาชิกและใช้ร่วมกันทุกสังกัด ตัวเลือกสมาชิกสำหรับซื้อแสดงสมาชิกโปรดด้านบน แต่ละสังกัดยังมีสีและราคาต่างกัน และรายชื่อแยกวงครบถ้วนยังอยู่ด้านล่าง รายการใหม่เลือกสังกัดโปรดที่ใช้ได้ก่อน การเชื่อมสมาชิกเดิมก็แสดงสมาชิกโปรดก่อน สมาชิกหรือสังกัดที่เก็บถาวรไม่อยู่ในทางลัดสมาชิกโปรด
- `isFavorite` ของสมาชิกเป็น Bool ไม่บังคับ มีเพียง `true` ที่หมายถึงโปรด ส่วน `false` การละฟิลด์หรือ `null` คือไม่โปรด JSON เดิมยังนำเข้าได้และ `schemaVersion` คงเป็น `1` ไฟล์สำรองทั้งหมดเก็บการตั้งค่านี้และปรับเมื่อรวมข้อมูลตามรหัสสมาชิก
- แอปใช้โหมดสว่างหรือมืดตามระบบในตาราง สมุดบันทึก บันทึกประจำวัน การตั้งค่า และทุกหน้าแก้ไข เลือก จัดการและสำรองข้อมูล เปลี่ยนตามระบบโดยไม่ต้องตั้งธีมแยก สีสมาชิกและสำเนาประวัติยังคงอยู่
