# การนำเข้าตารางเวลาด้วย JSON

[简体中文](IMPORT.zh-CN.md) | [繁體中文](IMPORT.zh-Hant.md) | [繁體粵語](IMPORT.zh-HK.md) | [English](IMPORT.en.md) | [日本語](IMPORT.ja.md) | [한국어](IMPORT.ko.md) | [ไทย](IMPORT.th.md) | [Bahasa Indonesia](IMPORT.id.md) | [Bahasa Melayu](IMPORT.ms.md)

ใช้ JSON ที่เข้ารหัส UTF-8 เปิดหน้านำเข้าจากตารางเวลา แล้ววางข้อความทั้งหมดหรือเลือกไฟล์ `.json` หรือข้อความธรรมดาหนึ่งไฟล์หรือหลายไฟล์ เมื่อตรวจสอบผ่านจะแสดงจำนวนอีเวนต์และช่วงกิจกรรม และจะนำข้อมูลไปใช้เมื่อกดยืนยันเท่านั้น หากแก้ไขข้อความในตัวอย่าง ต้องตรวจสอบใหม่

## การอัปเดตและรายการโปรด

เมื่อเปิดครั้งแรก แอปจะสร้างและบันทึกตารางเวลาสมมติสองตาราง โดยอิงชั่วโมงเต็มของเวลาโตเกียวขณะเปิด รวมตารางของวันถัดไป และเพิ่มสองวงแรกเป็นรายการโปรด หัวข้อไม่มีป้ายตัวอย่าง เมื่อเปิดครั้งต่อไปจะอ่านข้อมูลที่บันทึกไว้ การนำเข้าข้อมูลจริงครั้งแรกจะแทนที่ตารางที่ยังอยู่ในสถานะตัวอย่างและล้างรายการโปรดของตัวอย่าง การนำเข้าครั้งต่อไปจะเก็บอีเวนต์อื่นไว้ และแทนที่เนื้อหาทั้งหมดของอีเวนต์ที่มี `id` เดียวกัน เมื่ออัปเดตจึงต้องส่งข้อมูลอีเวนต์ครบทั้งอีเวนต์ ไม่ใช่เพียงบางช่วงกิจกรรม

`id` ของวงเป็นตัวระบุรายการโปรดร่วมกันข้ามอีเวนต์ หากเปลี่ยนชื่อแต่คง ID ไว้ รายการโปรดจะยังอยู่ แตะบล็อก LIVE หรือขายสินค้าสองครั้งเพื่อสลับรายการโปรดของวง ตารางของฉันรวม LIVE และขายสินค้าของวงในรายการโปรดตามอีเวนต์และวันที่ที่เลือก เวลาซ้อนกันเป็นข้อมูลที่ใช้ได้ โดยแสดงข้างกันพร้อมแจ้งเตือนเวลาซ้อน การแจ้งเตือนเปรียบเทียบเวลาเท่านั้น ไม่ประเมินการเดินทางหรือความเป็นไปได้ที่จะเข้าร่วมทั้งสองช่วง

## ฟิลด์

| ตำแหน่ง | ฟิลด์ | กฎ |
| --- | --- | --- |
| ระดับบนสุด | `schemaVersion` | จำนวนเต็มที่จำเป็น ต้องเป็น `1` |
| ระดับบนสุด | `events` | อาร์เรย์อีเวนต์ที่จำเป็น หน้านำเข้าต้องมีอย่างน้อยหนึ่งอีเวนต์ และอย่างน้อยหนึ่งช่วงกิจกรรมในชุดทั้งหมด |
| อีเวนต์ | `id`, `name`, `city` | สตริงที่จำเป็นและไม่ว่าง ID อีเวนต์ต้องไม่ซ้ำกันในชุดทั้งหมด |
| อีเวนต์ | `timeZone` | ต้องเป็นเขตเวลา IANA ที่ใช้ได้ เช่น `Asia/Tokyo` |
| อีเวนต์ | `venues`, `artists`, `sessions` | อาร์เรย์ที่จำเป็น อีเวนต์บางรายการไม่มีช่วงกิจกรรมได้ |
| สถานที่ | `id`, `name`, `color` | ID และชื่อที่ไม่ว่าง สีต้องเป็น `#RRGGBB` เช่น `#78C9EB` |
| วง | `id`, `name` | สตริงที่จำเป็นและไม่ว่าง ควรใช้ ID วงเดิมข้ามอีเวนต์ |
| ช่วงกิจกรรม | `id`, `artistID`, `venueID` | ID ช่วงกิจกรรมที่ไม่ว่าง ต้องอ้างอิงวงและสถานที่ที่ประกาศในอีเวนต์เดียวกัน |
| ช่วงกิจกรรม | `kind` | เป็น `live` หรือ `goods` เท่านั้น |
| ช่วงกิจกรรม | `startsAt`, `endsAt` | วันเวลารูปแบบ ISO 8601 แบบเต็ม มีวินาทีและ `Z` หรือค่าเยื้องเวลาชัดเจน เวลาสิ้นสุดต้องหลังเวลาเริ่ม |
| ช่วงกิจกรรม | `area`, `notes` | สตริงไม่บังคับ ละไว้หรือใช้ `null` ได้ |

ID สถานที่ วง และช่วงกิจกรรมแต่ละประเภทต้องไม่ซ้ำกันภายในอีเวนต์นั้น สตริงที่จำเป็นต้องไม่ประกอบด้วยช่องว่างเพียงอย่างเดียว JSON ไม่รองรับความคิดเห็นหรือจุลภาคท้ายรายการ ฟิลด์ที่ไม่รู้จักสามารถนำเข้าได้ แต่แอปไม่แสดงและไม่เก็บไว้เมื่อเข้ารหัสใหม่

## การตรวจสอบและนำเข้าเป็นชุด

ข้อผิดพลาดแสดงเส้นทางฟิลด์ เช่น `$.events[0].sessions[2].endsAt` เวอร์ชัน ชนิดข้อมูล วันที่ เขตเวลา สี ID ซ้ำ การอ้างอิง หรือระยะเวลาที่ผิดจะหยุดการตรวจสอบข้อมูลทั้งหมด หลายไฟล์จะถูกรวมแล้วตรวจสอบร่วมกัน ID อีเวนต์ซ้ำข้ามไฟล์ก็ทำให้ล้มเหลว หากไฟล์ใดล้มเหลวจะไม่เกิดการนำเข้าเพียงบางส่วน หน้านำเข้าไม่รับอาร์เรย์อีเวนต์ว่างหรือชุดที่ไม่มีช่วงกิจกรรมเลย รูปแบบระดับแกนกลางอนุญาต `events: []` เพื่อบันทึกสถานะว่างภายในหลังลบทั้งหมด

## เขตเวลาและช่วงที่ข้ามเที่ยงคืน

รองรับ `2026-10-14T12:00:00+09:00`, `2026-10-14T03:00:00Z` และเศษส่วนวินาที ค่า `12:00` หรือค่าที่ไม่มีวินาทีหรือเขตเวลาใช้ไม่ได้ ค่าเยื้องเวลากำหนดขณะเวลาที่แน่นอน ส่วน `timeZone` ของอีเวนต์กำหนดวันที่ท้องถิ่น ให้กรอกตามเขตเวลาจริงของแต่ละช่วง ชั่วโมงที่เกิดซ้ำจากเวลาออมแสง `2026-11-01T01:30:00-04:00` กับ `2026-11-01T01:30:00-05:00` เป็นคนละขณะเวลา

เมื่อข้ามเที่ยงคืน ให้ใช้วันที่ถัดไปในเวลาสิ้นสุด: `2026-10-14T23:40:00+09:00` → `2026-10-15T00:20:00+09:00` ช่วงกิจกรรมจะแสดงในทั้งสองวันที่ครอบคลุม โดยบล็อกถูกตัดให้พอดีกับแต่ละวัน หากสิ้นสุดตรง `00:00:00` จะไม่เพิ่มวันว่าง ไม่มีการกำหนดระยะเวลาสูงสุดโดยพลการ

หากเลือกอีเวนต์ต่างเขตเวลาพร้อมกัน หน้าจอปัจจุบันจะใช้เขตเวลาของอีเวนต์ที่ถูกเลือกและอยู่ลำดับแรกในเอกสารร่วมกันสำหรับวันที่ เวลา และรายละเอียด พร้อมแสดงเขตเวลานั้นในแถบตัวกรอง หากต้องการดูเวลาท้องถิ่นของอีเวนต์ใด ให้เลือกอีเวนต์นั้นเพียงรายการเดียว เส้นเวลาปัจจุบันใช้เวลาระบบจริง วันที่ของตัวอย่างแบบคงที่จึงอาจไม่ใช่วันนี้

## แก้ไขแม่แบบ

คัดลอกแม่แบบตารางเวลาจากลิงก์ท้ายเอกสาร คง `schemaVersion` และ `events` ไว้ กรอก ID ที่ใช้คงที่ แล้วคัดลอกช่วงกิจกรรมเพื่อแก้การอ้างอิง ประเภท และวันเวลา อีเวนต์ วง และตารางในแม่แบบเป็นข้อมูลสมมติทั้งหมด แม่แบบจะไม่ถูกนำเข้าโดยอัตโนมัติ
