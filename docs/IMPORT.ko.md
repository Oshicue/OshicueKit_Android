# 시간표 JSON 가져오기

[简体中文](IMPORT.zh-CN.md) | [繁體中文](IMPORT.zh-Hant.md) | [繁體粵語](IMPORT.zh-HK.md) | [English](IMPORT.en.md) | [日本語](IMPORT.ja.md) | [한국어](IMPORT.ko.md) | [ไทย](IMPORT.th.md) | [Bahasa Indonesia](IMPORT.id.md) | [Bahasa Melayu](IMPORT.ms.md)

UTF-8 JSON을 사용합니다. 시간표에서 가져오기 화면을 열어 전체 텍스트를 붙여 넣거나 하나 이상의 `.json` 또는 일반 텍스트 파일을 선택합니다. 검증에 성공하면 이벤트 수와 일정 수가 표시되며, 확인해야 적용됩니다. 미리 보기의 텍스트를 수정하면 다시 검증해야 합니다.

## 업데이트와 즐겨찾기

처음 실행하면 도쿄 현지의 실행 시각이 속한 정시를 기준으로 다음 날 일정까지 포함한 가상 시간표 두 개를 생성해 저장하며, 처음 두 그룹을 즐겨찾기에 등록합니다. 제목에 예제 표시가 나오지 않습니다. 이후 실행에서는 저장된 자료를 읽습니다. 첫 정식 가져오기는 예제 상태인 시간표를 대체하고 예제 즐겨찾기를 비웁니다. 이후 가져오기는 다른 이벤트를 유지하며 같은 `id`의 이벤트 전체 내용을 대체합니다. 업데이트할 때는 일부 일정이 아닌 이벤트 전체를 제공하세요.

그룹의 `id`는 이벤트 간에 공유되는 즐겨찾기 식별자입니다. 이름을 바꾸더라도 ID를 유지하면 즐겨찾기가 이어집니다. LIVE 또는 굿즈 판매 블록을 두 번 탭하면 해당 그룹의 즐겨찾기가 전환됩니다. 내 시간표는 선택한 이벤트와 날짜에 따라 즐겨찾기 그룹의 LIVE와 굿즈 판매 일정을 함께 표시합니다. 시간 중복은 허용되며 나란히 표시되고 중복 안내가 나옵니다. 안내는 시간만 비교하며 이동이나 두 일정 모두의 참석 가능성을 판단하지 않습니다.

## 필드

| 위치 | 필드 | 규칙 |
| --- | --- | --- |
| 최상위 | `schemaVersion` | 필수 정수이며 항상 `1`입니다. |
| 최상위 | `events` | 필수 이벤트 배열입니다. 가져오기 화면에서는 이벤트 하나 이상과 전체 묶음에 일정 하나 이상이 필요합니다. |
| 이벤트 | `id`, `name`, `city` | 필수이며 비어 있지 않은 문자열입니다. 이벤트 ID는 전체 묶음에서 고유해야 합니다. |
| 이벤트 | `timeZone` | `Asia/Tokyo` 같은 유효한 IANA 시간대가 필요합니다. |
| 이벤트 | `venues`, `artists`, `sessions` | 필수 배열입니다. 개별 이벤트에는 일정이 없어도 됩니다. |
| 공연장 | `id`, `name`, `color` | 비어 있지 않은 ID와 이름이 필요합니다. 색상은 `#78C9EB`처럼 `#RRGGBB` 형식이어야 합니다. |
| 그룹 | `id`, `name` | 필수이며 비어 있지 않은 문자열입니다. 그룹 ID를 이벤트 간에 일관되게 유지하세요. |
| 일정 | `id`, `artistID`, `venueID` | 비어 있지 않은 일정 ID가 필요합니다. 해당 이벤트에서 선언한 그룹과 공연장을 참조해야 합니다. |
| 일정 | `kind` | `live` 또는 `goods`만 허용됩니다. |
| 일정 | `startsAt`, `endsAt` | 초와 `Z` 또는 명시적 오프셋이 있는 완전한 ISO 8601 날짜·시간입니다. 종료는 시작보다 늦어야 합니다. |
| 일정 | `area`, `notes` | 선택 문자열입니다. 생략하거나 `null`로 설정할 수 있습니다. |

공연장, 그룹, 일정 ID는 각각 해당 이벤트 안에서 고유해야 합니다. 필수 문자열에는 공백만 넣을 수 없습니다. JSON은 주석과 마지막 항목 뒤 쉼표를 지원하지 않습니다. 알 수 없는 필드는 입력할 수 있지만 앱에 표시되지 않으며 다시 인코딩할 때 보존되지 않습니다.

## 검증과 일괄 가져오기

오류에는 `$.events[0].sessions[2].endsAt` 같은 필드 경로가 표시됩니다. 버전, 자료형, 날짜, 시간대, 색상, 중복 ID, 참조 또는 시간 길이에 오류가 있으면 입력 전체의 검증을 중단합니다. 여러 파일은 합친 후 함께 검증하며, 파일 간 이벤트 ID 중복도 실패합니다. 어느 파일이든 실패하면 일부만 가져오지 않습니다. 가져오기 화면에서는 빈 이벤트 배열이나 일정이 전혀 없는 묶음을 적용할 수 없습니다. 기본 형식은 모두 삭제한 뒤 내부 빈 상태를 저장하기 위해 `events: []`를 허용합니다.

## 시간대와 자정을 넘는 일정

`2026-10-14T12:00:00+09:00`, `2026-10-14T03:00:00Z` 및 소수 초를 허용합니다. `12:00`, 초 또는 시간대가 없는 값은 유효하지 않습니다. 오프셋은 절대 시각을 결정하고 이벤트의 `timeZone`은 현지 날짜를 결정합니다. 각 일정의 실제 시간대에 맞춰 입력하세요. 서머타임의 반복 시간 `2026-11-01T01:30:00-04:00`와 `2026-11-01T01:30:00-05:00`는 서로 다른 두 시각입니다.

자정을 넘으면 종료에 다음 날짜를 적습니다: `2026-10-14T23:40:00+09:00` → `2026-10-15T00:20:00+09:00`. 일정은 걸쳐 있는 양쪽 날짜에 표시되며 블록은 해당 날짜 범위로 잘립니다. 정확히 `00:00:00`에 끝나면 빈 날짜를 추가하지 않습니다. 인위적인 최대 길이 제한은 없습니다.

서로 다른 시간대의 이벤트를 함께 선택하면 현재 화면은 선택한 이벤트 중 문서 순서상 첫 이벤트의 시간대를 날짜, 시간, 상세에 공통으로 사용합니다. 필터 표시줄에 해당 시간대가 나옵니다. 이벤트 자체의 현지 시간을 보려면 그 이벤트만 선택하세요. 현재 시간선은 실제 시스템 시각을 사용하므로 고정 예제 날짜가 오늘이 아닐 수 있습니다.

## 템플릿 편집

문서 끝에 링크된 시간표 템플릿을 복사합니다. `schemaVersion`과 `events`를 유지하고 일관된 ID를 입력한 뒤, 일정을 복사해 참조, 종류, 시각을 수정하세요. 템플릿의 이벤트, 그룹, 일정은 모두 가상이며 자동으로 가져오지 않습니다.
